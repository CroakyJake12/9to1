# Trace native CUI entry points

Identify how the user reaches the interface before changing it. Haven’s top tab strip, Home’s settings and Spaces Chat each link to an actual CUI document. A separate executable can reuse a route by borrowing its provider and native host lifetime. Learn which is active from the startup composition and selected app.

For a route migration, read the current document, state bindings and action dispatcher. Verify opening, user input, save/restore and close through the integrated app. Recheck any historical launcher matrix against the current checkout and installed candidate before treating the route as ready.

## Additional native routes

Write and Present have dedicated executable entry points that call the original Desktop bootstrap. Their app-specific native publication must retain the Home lease, provider and document workspace. Boards has an app CUI source tree and a retained HUI scene boundary. Canvas has a native viewport and a separate Rnote engine bridge. Frame retains the Picture directory and route for compatibility. Wave requires a real project/Files attachment for editing.

Use each app’s guide to check its actual startup and dependency boundaries; a successful standalone fixture is not the application being available in every host.
