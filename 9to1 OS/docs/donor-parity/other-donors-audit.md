# Other-donors audit — Browse / Write / Data / Present / Plan / Terminal / Dev / WinBoat / Wine / Wave-Motion / Images

Question asked: for each app, is it class **A (donor-UI-migration**, faithful HUI reconstruction owed) or class **B (backend-integration**, headless engine/worker behind HUI-owned UI), and — where the checkout gives evidence — how severe is the "kept backend + invented simplified frontend" violation?

Method: `git ls-tree -r HEAD -- apps/`, `apps/COMPONENT-RELEASE-EVIDENCE.md`, `apps/Data/README.md`, `apps/present-engine/README.md`, `docs/MIGRATION.md`, `havenos.lock` (all read in this worktree). There is no Browse/Write/Plan/Terminal/Dev/WinBoat/Wave/Images source in this checkout, so most rows are classifications with *no verdict possible here* — recorded as BLOCKED rather than inferred.

Severity scale: `NONE` = pattern correct, no violation. `LOW` = proof/doc gap only. `MEDIUM` = simplified UI could be mistaken for donor parity (needs parity record, which this audit supplies for Canvas/Boards). `HIGH` = backend bypassed/emulated, or licence/containment boundary crossed. `BLOCKED` = no implementation in this checkout to judge.

## Cross-cutting rules for the next workers (all apps)

1. **B-class apps must look like Data/Present**: headless engine in a worker process (disposable profile, bounded protocol, no engine UI toolkit in HUI), HUI owns all pixels, engine types never cross the HUI boundary, versions pinned and enforced at runtime (DuckDB 1.5.5 pattern), no image/VM/package claims without evidence.
2. **A-class surfaces (Canvas tools, Boards interactions, HUI widgets) must carry a parity matrix** before any "parity" language is used; a simplified HUI surface without one is a MEDIUM violation by default.
3. **Write stays BLOCKED** until an authoritative Writer-backed slice lands; do not backfill it from Data/Present code or from memory of Writer UI.
4. **Licence boundaries**: AppFlowy-Board neutrality (MPL, no donor classes in schema) is the template; Rnote GPL-3.0-or-later engine boundary (C ABI, no `ui` feature) likewise. Future donors need a `THIRD_PARTY.md`-equivalent before integration.
5. **Absent ≠ failed**: rows marked BLOCKED are scope statements, not accusations. The violation this audit was asked to find is confirmed only for Canvas/Boards HUI surfaces (simplified vs donor), and both now have matrices that bound the debt without discarding the proven backends.
