# AppFlowy parity matrix — donor `AppFlowy-IO/appflowy-board @ 804d789` (v0.1.2) vs CakeOS Boards

Donor scope is deliberately narrow: the pinned package is a Kanban board *widget + controller* (`lib/`), not the full AppFlowy app (no database, no collab, no filter/sort/group-by, no card properties, no persistence, no menus). CakeOS side = `apps/Boards/contract/*` (neutral snapshot/commands/reducer/store/adapter), `apps/Boards/hui/*` (structured + freeform HUI scenes + session), `apps/Boards/appflowy_poc/lib/*` (Flutter proof harness hosting the real package). Per `THIRD_PARTY.md`, no donor source is copied; the package is referenced by exact commit and must not become the persistence schema.

Status key: `PASS` = donor behaviour reachable today (often proven in the PoC via the real package, with HUI button-equivalents alongside). `PARTIAL` = subset or PoC-only without neutral-contract coverage. `MISSING` = donor capability unused or absent. `BLOCKED BY BRIDGE` / `BLOCKED BY HUI` = the Flutter↔neutral seam (adapter) or the HUI projection is the blocker. Donor-absent areas are marked `PASS` with a "vacuous" note where there is nothing to reconstruct, so parity debt is not confused with app scope.

## What "faithful" means for the next worker

1. Add neutral commands + reducer cases + session paths for `CreateGroup` / `RemoveGroup` / `DeleteCard` / `RenameCard` (and `RenameGroup` exists already) — the only structural parity gaps.
2. Keep the PoC as the donor-behaviour proof (real package drags → adapter → persist → reopen) and the HUI scenes as the product projection; do not merge the Flutter widget into the product path.
3. Adopt donor options only on app demand: footer builder, background, leading/trailing, pagination (large boards), `scrollToBottom`, `enableGroupDragging`, `onStartDraggingCard` telemetry.
4. Keep persistence neutral (`snapshot` JSON + `.rnote` bytes + viewport, same-dir atomic replace); never persist donor controller classes.
5. Card properties, filter/sort, menus, and board settings are app scope with no donor template — design them in HUI/contract terms, not by copying AppFlowy app code (which is outside the pinned package and differently licensed).
