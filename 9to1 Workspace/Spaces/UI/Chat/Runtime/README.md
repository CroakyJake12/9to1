# Canonical Spaces CUI adapter

This adapter registers the actual shared `CuiMarkdownView` as `Object Type="ChatMessageContent"`. It does not install a Markdown substitute, authorize code, create a conversation store or register a product route. Its code controls use the existing CUI template/property/state system. An omitted code-action owner disables Copy/Ask to run/Ask to apply. A supplied owner must enforce clipboard/permission/execution policy and check the current message/request context. The retained shared renderer's current Markdown and accessibility limits remain applicable; this is not a full rich-text or LaTeX acceptance claim.

`AttachComposer(root)` attaches Enter handling only to the actual focused `composer-input` and raises the authored `send` button's event. Shift+Enter remains a newline. Dispose this attachment before retiring the surface. The host must install its normal action availability observer and retain the loader's real asynchronous dispatch lifetime. An unavailable send remains unavailable on keyboard input.

The canonical Home and Chat documents preserve existing IDs, owner commands and state paths, with these explicit contracts:

- `layout.columns` is a canonical grid-track string; `layout.sidebarVisible` and `layout.sidebarHidden` are complementary presentation observations. Desktop defaults to `280 1fr`; collapsed uses `0 1fr`. The host handles width/responsive drawer decisions and persisted sidebar preference. The `spaces.toggle-sidebar` and `chat.toggle-sidebar` intents must change that same owner state, without changing conversation/draft identity.
- Home's `spaces.query`, Chat's `recentQuery` and `composer.draft` are two-way owner bindings. Search filtering and draft durability remain owner operations.
- Home repeated collections keep the existing `spaces.builtIns`, `spaces.customSpaces`, `selection.contextReferences` and `selection.capabilities` paths. Space rows expose canonical `id/name/summary/isCurrent`; context and capability rows now also require stable `id`, alongside existing label fields. Reorder does not create new canonical records.
- Chat message/recent/attachment records use the existing typed owner's PascalCase properties. The runtime resolves row-scoped action arguments from the same stable keyed record. No display label becomes an identity.
- `modelLabels` and `branchLabels` are display strings projected by the owner from the same current `models` / `conversation.branches` snapshot. `composer.selectedModelIndex` and `conversation.selectedBranchIndex` are two-way UI indexes only. On write, the owner must bounds-check the index against that snapshot, dispatch existing `chat.select-model` / `chat.switch-branch` with its canonical model name/branch ID, and publish the resulting canonical selection. A stale, denied or unavailable choice must not become a successful local selection. Existing `composer.selectedModelName` and `conversation.currentBranchId` remain canonical observations.

The model/branch selection uses real CUI `Input Type="Select"`. The current CUI Repeat implementation produces a structural panel; it cannot be inserted as fake dynamically repeated MenuItem children while claiming keyboard menu semantics.

The executable `Tests/Rendering/SpacesCui.Render.Tests.csproj` strictly compiles these public documents and renders/operates their actual controls through explicit fixture bindings. Its saved images are marked fixtures. It covers populated desktop/compact/narrow geometry, Professional/Glow, canonical row action identity, reorder identity, actual input writeback, theme/stream focus and selection preservation, Enter/Shift+Enter and disabled/disposed submission. It establishes no provider, persistence, deployed, native package or complete product acceptance. Revised rail, customizable sidebar, floating Summary, Tabs, voice, rich composer, Builder, Study and task/assistant integrations remain separately required.

## Production Manage Spaces binding

The browser manager selects catalog records with `spaces.select` and the row's canonical `space.id`. It opens a workspace only through `spaces.open` with `selection.id`; `selection.canOpen` must be false unless an actual product owner is registered, and `selection.unavailableReason` explains the unavailable route. Selecting a record is not launching a workspace.

The inline create/rename editor uses `editor.visible/title/name/description/error/canConfirm`. Name and description are two-way owner values; `spaces.confirm-edit` persists through the real registry, while `spaces.cancel-edit` abandons only this form. The owner validates name uniqueness and length and preserves unsaved input after a failed write. Archive visibility is `spaces.showArchived`; rows expose complementary `isActive/isArchived`, with `spaces.restore` acting on the original `space.id`. Fork/archive/restore do not duplicate or remove conversation history. Unsupported move/context actions must be unavailable through the action availability observer. `home.open` delegates to the existing `ShellHome` owner.

The same runtime project includes `HavenOS.Apps.Spaces.Rendering.SpacesHomeCuiRuntime.AttachEditor(root)`. A host mounts the actual CUI root and retains/disposes this presentation attachment with its loader lifetime. It focuses the real name input when an editor is opened, guards focus restoration against deliberate intervening focus, and sends scoped Escape/Ctrl+Enter through the authored Cancel/Save buttons. A disabled Save cannot run through the keyboard. This attachment cannot validate a name, grant an operation or persist a record. The inline form is not a modal dialog.

Hosts must set `loader.SetSurface("Spaces", "app.spaces")` so the existing Spaces theme palette and app preference context apply. Theme selection still comes from Home; this adapter does not impose an application-specific theme.

The editor attachment optionally accepts `viewportWidthChanged`. It reports the actual mounted root's positive width and stops observations when disposed. The browser manager owns compact layout decisions; `layout.detailsVisible` hides the details pane when its compact list is open. The renderer fixture's explicit width state is not proof of production responsiveness; the host must connect these observations to the actual session.
