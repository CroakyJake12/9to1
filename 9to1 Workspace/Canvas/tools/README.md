The donor capability inspector reads the controlled Rnote revision and generates `Canvas/RnoteCapabilityInventory.json`. Run `python3 tools/inspect_rnote_capabilities.py` from Canvas to regenerate, or append `--check` to detect stale inventory. It verifies the exact donor commit and hashes all inspected Rust/UI files; it never changes donor source.

The inventory classifies discovered action declarations and authored UI surfaces. Ordinary GTK controls require CUI equivalents; applicable donor editing actions remain preservation requirements. The source-inspected nine colour-setter action names are retained as a dynamic family. No entry has verified native parity evidence, and no not-applicable exception is accepted. `releaseConformance` deliberately remains false until runtime journeys and an exhaustive behavioural audit cover engine, input, format and platform capabilities that source-action discovery cannot establish.

`Stage-OriginalWindowsNativeKit.ps1` stages the exact Windows x64 ABI3 native kit into an already published genuine Home graph containing Canvas. Supply `OriginalKitRoot`, `OwningHomePublishDirectory`, and the actual `OwningHomeExecutableName` when its name differs from the existing `AvaloniaHome.exe` default. The helper validates the owner executable's x64 PE header, its matching win-x64 dependency manifest, the Canvas host dependency, and every native file's size/hash before copying. It preserves the original kit and includes its dependency licenses and provenance.

Immutable byte staging can run on the cloud host. It does not issue Home admission or prove that the Windows artifact launches, draws, saves or reopens; the stage receipt keeps application smoke unrun until the actual Windows artifact is exercised.
