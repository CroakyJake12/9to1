# Explicit Saved Agent migration

This module connects the actual legacy SQLite `agents` catalogue to the existing configured Assistant/Specialist definition in the same current personal Home Den. Its contracts project has no Infrastructure or Desktop dependency. The implementation borrows the configured protected canonical SQLite owner, Home ownership authority, current Home actor, Den factory and the same presentation's `DenAssistantCanonicalBridge`.

The native/web entry point is a migration review inside Assistants. It must not restore the retired Agents product. The native owner renders `ILegacyAgentMigrationController` and routes acknowledged Assistant results back to the existing Assistants controller. Specialists retain their separate product type; the migration view must not open one as an Assistant.

## Source setup

Construct `LegacySavedAgentSqliteSource` with the application's same `CanonicalSqliteOriginalStoreOwner` and actual `HomeLocalProfileIdentity`. The generic owner captures the same configured `SqliteDatabase` and `IAppPaths`; the adapter verifies the original profile reference. Construction does no I/O. Register that exact adapter instance as a Home local-store evidence provider before Home composition. No arbitrary database path is accepted by the migration API.

The immutable `canonical.sqlite.store-identity.v1` metadata is created only by the real normal `SqliteDatabase.InitializeAsync` owning write transaction. The adapter's `PrepareIdentityAsync` compatibility setup method only validates an existing identity. Neither navigation nor import inspection creates identity, repairs a schema, changes permissions, adopts an existing store or invokes the initializer. Missing/corrupt identity remains unavailable. An identity is not evidence of Home ownership or an empty store.

Every actual read uses the generic owner's original native handle/ACL custody and transaction, current Home actor, raw source tasks and postguard checks. The migration adapter holds its original immediate SQLite writer reservation across a confirmed Den CAS, while modifying no legacy rows. Actual reader results acquired after a caller postguard failure remain captured and disposed; operation and independent cleanup faults are both retained.

Use the existing `HomeLocalStoreSetupSession` with resource kind `legacy.saved-agents`, the same source as identities/evidence, and the same Home profiles/ownership. The populated source requires Home's existing RequestImport → user review → CompleteImport operation. Its evidence hashes actual definition, run and linked memory rows. Do not infer this source's ownership from a Den receipt. The migration controller refuses source reads until its actual current Home ownership receipt is valid.

## Explicit review and recovery

List pages are bounded. Preview reads the actual selected SQLite row, including disabled and built-in entries, without seeding the catalogue. It supplies the original definition, compatible review notes, scoped-memory/run availability and preserved links. No Assistant/Specialist type is inferred or preselected. The source-issued preview is an opaque current presentation object; constructing IDs or reusing another view's preview does not authorize conversion.

Confirmation compares the exact source definition fingerprint and actual destination revision, reserves the original SQLite writer while checking/committing, and preserves the stable legacy GUID. An unrelated Den record with that GUID is a collision, regardless of name or record type. The first Den write stages the original row's complete raw fields, original store/row identity, profile and the user's exact operation/type/configuration. The existing canonical classifier supplies configured product metadata and captures its unclassified before-state. The module does not create another definition serializer, chat engine, task store, model router or permission system.

Legacy SQLite definitions, runs, conversations/messages, knowledge records, provenance/privacy/retention metadata, retrieval records and resource references remain in their original owners. `ReadPreservedLinksAsync` reads current links through the owned source; these are durable references and display observations, never membership, execution or resource grants. Natural conversation adoption must use a genuine canonical source-owner membership operation; this module does not invent authority from an activity JSON `ContextId`. Legacy API availability remains intact through April 2027.

Interruption after a successful stage leaves that original state inspectable. A fresh preview reports `PendingClassification` with the already confirmed type and operation. Continuing is a new explicit action over that exact choice and unchanged source; it does not automatically replay an unknown write. A changed source or choice refuses. An acknowledged classification can be reviewed for undo. On reopening, preview returns `ClassifiedDefinition` from the SAME actual canonical bridge; the UI does not reconstruct a destination identity. Undo restores the exact unclassified Den before-state only while the classified definition is unchanged and no continuing canonical conversation, run or memory exists. It never deletes history. Both preview and commit check this restriction. A restrictive policy over the **same** Den store and original Home policy repeats the checks under the actual Den writer lease and immediately before publication, so a previously reserved conversation prevents undo. Reads in that callback use the original policy and do not acquire the writer lease; never call Home.Open or Den ownership observation inside it.

## Original custody and integration

The per-view migration controller serializes its own commands, retains their actual source Tasks, seals admission on retirement and joins them independently. SQL commands/readers, transactions and connections preserve both operation failures and independent disposal failures. The adapter owns and joins only its own setup originals and per-operation protected leases. Application composition joins the shared SQLite owner after its borrowers; the migration view does not retire borrowed Home, SQLite, Den, chat or task owners.

Native/web presentation must inspect `IsAcknowledgedOriginalCommandRefusal` on the **same returned Task**, immediately after observing a refusal. Only the controller's exact locally issued pre-effect refusal with settled original sources qualifies. Foreign failures, reused exception objects, mixed failures and partial effects remain failed originals. Demand external join, retire and join the migration controller before retiring its borrowed canonical bridge/Core controller.
