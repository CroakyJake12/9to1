# 9to1OS Dev app surface

This directory owns the independent 9to1OS Dev domain surface. It currently provides versioned multi-root workspace persistence, provider-driven project-template discovery with preflight toolchain readiness, a stage-oriented task executor, and a code-intelligence adapter over 9to1's maintained language service.

The canonical workspace path also connects the maintained source editor, reviewed text edits, saved build stages, tests, Git observations and terminal commands to the existing Task/Run. The native workbench is composed by the Desktop owner over the same Dev, Files and canonical task services; its presence does not register a separate Dev App launch or grant workspace execution.

## Current capabilities

- Workspace and project records use stable IDs; workspace files are versioned, atomically saved, and protected from stale writers.
- Project templates can be registered by providers and filtered by language, framework, platform, product surface, search text, and toolchain readiness.
- Task execution validates dependencies, requires workspace trust where declared, requests Home authorization before executing, enforces stage timeouts, and returns stage-level states and diagnostics.
- Code intelligence delegates semantic operations to the existing advanced service. Code actions and semantic rename previews retain immutable proposals for explicit Home-approved application; source/version conflicts refuse stale proposals. The native manual workbench does not call the raw language-server provider: it still needs a genuine read/process admission adapter.
- Structured results carry stable error codes, target IDs, retry metadata, and request IDs.
- A Space can persist a reference to the original workspace/project/root and canonical Task/Run. Fresh reopening reads the existing stores and current task observation; it does not create a workspace, task or attempt. A revision conflict requires an explicit current-reference attachment through the owning service.

### Current Build editor and saved-project navigation

The compiled-CUI Build landing presents every saved project/root/repository choice, including its actual location and environment. Filtering and bounded pages select metadata only. Manual Open passes the exact revision-bound reference to the existing host callback, which resolves and checks current access again. A failed manual census is shown as unavailable and cannot enable new setup. Typing a folder path is a candidate for the genuine Files/Home setup adapter, not authorization.

The workbench keeps per-document draft Undo/Redo, literal Find/Replace, protected conflict/merge recovery, and explicit source review. Current CUI drafts can use the authoritative parser for Problems and component-outline navigation. The property inspector edits existing literal attributes on uniquely named built-in components in XML-shaped CUI, preserving all source outside the selected attribute value. Bindings, shorthand and unsupported structured values remain code-defined. Changes enter the same unreviewed draft, Undo and recovery owners; no source write occurs until the normal reviewed apply path.

These CUI checks and property edits are bounded authoring tools, not a full compiler, visual canvas, runtime preview or language-server admission. Saved RunConfiguration/PreviewProvider metadata alone does not supply a native launch/preview owner. Manual project creation from templates, arbitrary new-file creation, target-specific Run and full visual designer workflows remain open until their real owning adapters are connected. Focused owning tests must be compiled/run for the exact integrated source; this description makes no acceptance claim.

## Ownership and integration limits

Dev does not replace Files, Stack, Terminal, Sites, AI Studio, Home, or extension hosting. Providers must connect the domain seams here to those owning services. The native workbench has source editing and reviewed per-pass inverse preparation through the maintained owner. A separate registered Dev App launch, full project wizard, toolchain installer, DAP debugger, Test Explorer, package providers, Stack review UI, CUI builder, remote environment adapters and exhaustive first-party API/event catalogue remain open implementation requirements.

Canonical project tree and text search currently refuse: the physical original workspace owner has no safe per-child traversal port. The workbench's tree/search commands do not establish that capability. Source reads and edits still require the actual configured Files identity resolver, original task admission and current native fences. Process acceptance is distinct from an observed successful build or test exit.

The source editor and shared UI/runtime are owned by their existing workspace and platform layers. Dev's domain APIs must be wired into those layers through their owners; this project adds no alternate editor runtime or platform-specific dependency. Visual Studio extension provenance remains outside this package.

## Bounded original project traversal candidate

The baseline traversal refusal described above is superseded in this source candidate by `WorkspaceToolService.OriginalTraversal.cs`. The canonical original owner makes `list_files` and `search_files` available only through the actual optional traversal source and its privately issued read fence. The per-call port preserves the same canonical Task/Run/action, fresh actor/model/root observations and the maintained central permission gate. It issues no mutation receipt or checkpoint. Standalone Dev launch and additional presentation bindings remain outside this connection.

Linux reads directory names through the held directory descriptor and opens each child with `openat2` beneath that same handle, refusing symlink, magic-link, mount and hard-link aliases. Windows reads native directory records from the held directory handle; retained ancestors exclude rename/reparse substitution, and file identity/link-count checks guard the held read. Windows requires the observed case-insensitive directory and supported native record APIs. Linux detects observed path/inode/version changes; it does not promise exclusion of external writers. Unsupported native paths fail closed.

Read coverage is explicit: depth at most 10, at most 2,000 enumerated entries, at most 200 matches, at most 2 MiB per searched file and 16 MiB total. The original action has finite validation custody, so the traversal uses at most 48 fresh read revalidations and reports when that limit truncates coverage. Ignored folders, large files and binary/invalid UTF-8 exclusions are counted; the runtime preserves that coverage footer inside its existing 120,000-character output bound. Permission, identity, I/O and cleanup failures are errors rather than successful empty scans. All source validation/read/disposal tasks settle before original outcome acceptance.

Owning controls are `WorkspaceOriginalTraversalTests` in `Haven.Infrastructure.Tests` and `WorkspaceTaskRunTraversalTests` in `Haven.Core.Tests`. They require fresh normal owning builds and tests on supported Linux and Windows hosts; this source packet does not claim SDK, native, UI or actual model-backed takeover validation.

## Protected dirty-draft recovery storage (implementation groundwork)

`DeveloperWorkspaceStore.DraftRecovery.cs` adds bounded AES-GCM recovery payloads inside the existing canonical workspace document. Recovery has a separate optimistic generation; normal workspace and clean-session saves preserve it. A current unchanged project may rebind after an unrelated workspace metadata update. A changed project/root/repository, stale generation, malformed ciphertext or full native one-MiB document refuses without replacing prior recovery. Partitions include the real Home profile and canonical Task/Run/context; no previous snapshot is evicted to make room. Payloads retain complete draft text, baseline content hashes, tab order/pins and selection, with a 128-KiB UTF-8 JSON limit. Oversized drafts are refused, never truncated.

The pure protect/unprotect functions require the actual trusted host's 256-bit protected key. They never generate/store a key, accept a password, use an insecure settings-encryption fallback, copy drafts into raw Den records or create another store. Ciphertext authenticates every header field, including exact project observation, scope and generation. Storage shape checks cannot prove current authority or ciphertext authenticity: only genuine original Home/source/task admission and successful decryption can do those jobs.

The manual (no-AI) workbench now composes the original Home/Files/kernel READ owner and the actual Linux descriptor-backed or Windows Credential Manager owner for protected draft save/restore. The same canonical workspace lock serializes protected-key get/create, so racing writers cannot replace an accepted key; a missing/malformed key is never reset while this profile already has recovery. The existing execution reservation and page command fence separate canonical metadata updates from live commands. One coalesced 600-ms page-owned driver saves complete dirty snapshots and preserves newer typing while older saves settle. On reopening, every baseline is freshly authorised and hash-checked. Matching baselines restore all-or-nothing and unreviewed. If any readable source changed, the shared CUI workbench stages the complete protected snapshot in a recovery tray: current source, retained draft and both revision hashes remain separately inspectable. Nothing is rebased or applied automatically. “Use recovered draft against current source” performs another genuine READ and requires reinspection if the source changed again; only that explicit choice enrolls an unreviewed editor draft. A dirty already-open tab or full editor capacity refuses adoption without discarding either draft. The original encrypted multi-tab snapshot stays unchanged until every pending draft has been explicitly reconciled and a new complete payload is acknowledged. Source writes still need the existing explicit review/Home WRITE flow. Whole-page close remains vetoed until the exact latest complete payload is acknowledged; individual dirty-tab close still refuses implicit discard.

**Implementation limits:** Task-backed autosave is still unwired because its original command READ bindings/pins retain the canonical metadata identity. Missing/unreadable source, missing keys, payload/document limits, denied actors and stale CAS still block recovery rather than discard prior encrypted evidence or relax source authority. Changed readable baselines now have explicit manual reconciliation; automatic merging, missing-file recreation and task-backed reconciliation remain unimplemented. Native OS credential access, genuine end-to-end restore/debounce/normal close, cross-platform behavior and compilation of these new host paths still need their actual owning checks. A copied scope tuple is never permission, and no SDK/native/acceptance/release pass is claimed by this source implementation.

Focused controls in `Tests/DeveloperWorkspaceDraftRecoveryTests.cs` cover ciphertext restart, header/key tampering, profile/task partitioning, stale and concurrent CAS, ordinary/clean-save preservation, changed-project refusal, payload/document bounds, invalid paths, corruption and cancelled writes. They were **authored, NOT RUN** for this implementation packet. No SDK, native, protected-key, UI, acceptance or release success is claimed.

Manual host controls in `shared/tests/Haven.Desktop.Tests/DeveloperManualDraftRecoveryTests.cs` are authored **NOT RUN**: key preparation follows canonical CAS, another task's existing profile recovery prevents key reset, manual ciphertext cannot borrow task scope, older acknowledgements do not match newer typing/selection, and substitute credential providers are refused before secret/source access. These are bounded domain/custody controls, not simulated native success.

## Original metadata-transition provenance for task-backed recovery

Protected recovery saves now issue an optional opaque metadata-transition receipt from the SAME canonical store after the actual atomic writer succeeds. It records exact raw before-document SHA-256, the exact serialized bytes passed to that writer, and the unchanged complete Workspace authority projection. The existing writer validates that projection before effect. Private same-store/reference membership and the actual successful write Task distinguish original provenance from copied records, interface implementations and foreign stores. This is **in-process historical provenance, not current native authority**. It neither edits source nor updates a Task/Run, Home READ identity, execution binding/pin or cold capsule. Reopening a process requires fresh owning reconciliation; serialising the receipt is not a recovery shortcut.

## Actual Task workbench draft recovery caller (implementation candidate)

Native task workbenches now receive a page-owned `DeveloperTaskDraftRecoveryOwner` from their existing factory. It uses the configured original Task coordinator, real current issued attempt and revalidated lease, persisted conversation/container, genuine Home command READ, original Files execution bridge, canonical workspace store and actual platform key owner. The READ actor must match the actual Task owner. It creates no replacement Task/Run/model, alternative store or credential provider. The existing source editor's open/preview/apply/terminal/test/Git calls enter a finite original command READ frame; they retain the actual source task and original workspace command fence. Existing non-native/test compositions retain their own old provider behavior and confer no new native authority.

Task recovery is partitioned by the actual personal profile, Task, Run and context. Restart first reads that same protected partition and freshly prepares each matching-baseline source before restoring unsaved text as an unreviewed draft. No pass, execution approval or old write decision is restored. A changed baseline preserves the encrypted snapshot and refuses substitution; unlike the manual recovery tray, a task conflict reconciliation tray is not yet wired. Missing/invalid keys remain intact and no substitute provider is consulted. Cold-recovered tasks must first acquire their genuine current issued attempt through the existing canonical recovery path; IDs alone never suffice.

One page-owned 600 ms coalesced driver captures the complete bounded tab payload. Each save establishes a genuine idle command cohort, verifies current source baselines, acquires the original workspace metadata fence, obtains the platform key under canonical CAS, performs the same atomic metadata replacement and joins original Home/Files after-native rebind plus a distinct initial-input READ. It closes only its own old command READ. The live tab text is never overwritten by an older acknowledgement. Only an exact latest complete acknowledged protected payload clears the dirty-close veto. New typing, pin/selection changes and an error/unknown source outcome keep the appropriate protection; no unknown save is automatically replayed.

Existing protected terminal capsules are deliberately preserved. Before metadata effect, a real journal observation must show no existing capsule and the Home source must admit an initial-input metadata mutation. This reservation excludes in-flight terminal identity captures and refuses an already sealed capture; a later capture waits for its genuine successful successor or observes the original failure. Thus absence checks cannot race an old terminal identity publication. No already-published capsule or resumed-material migration is implemented. If such a capsule exists, keep the draft open and use the existing explicit source review path; it is not silently made current.
