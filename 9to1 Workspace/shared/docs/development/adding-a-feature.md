# Add or change a native feature

1. Identify the user’s route, action, object and expected outcome in the current product register.
2. Find the existing domain service, repository and typed action. Trace the standalone and embedded hosts where both are supported.
3. Extend canonical CUI and its bindings for presentation. Keep OS-specific concerns in the existing adapter. Preserve compatible behavior and user data.
4. Test a real success, a denied or unavailable case and the result of closing the view with pending work.
5. Build through the guarded procedure and inspect the changed route. Record which behaviours were actually observed.

For a new tool or shared default, establish who grants access, stores the value and reports completion. UI visibility does not grant runtime permission.
