# Efficient-training research and admission notes

Primary sources inspected 2026-11-16. These are method-selection notes, not measured results on Jacob's hardware. No implementation below was downloaded or vendored. `core.py` is an independently authored small CPU correctness prototype using installed PyTorch; it does not claim to implement these papers wholesale. Pin exact package revision, complete license/notice and dependency closure before incorporating a third-party adapter.

| Method | Primary evidence and distinction | License/admission status here |
|---|---|---|
| BAdam | [Paper](https://arxiv.org/abs/2404.02827), [authors' repository](https://github.com/Ledzy/BAdam). Uses block coordinate descent with Adam; switching frequency is part of the algorithm. Repository notes that default blocks omit embeddings/head. Complete-parameter coverage therefore needs explicit audit, not a claim based on one schedule cycle. | Repository page declares Apache-2.0; guessed raw LICENSE paths returned 404, so complete redistribution notice and exact revision remain to acquire before reuse. Not installed. Our coordinate implementation retains ordinary per-parameter Adam state and is not a BAdam adapter or its claimed memory behavior. |
| GaLore | [Paper](https://arxiv.org/abs/2403.03507), [authors' repository](https://github.com/jiaweizzhao/GaLore). Projects gradients into a lower-rank subspace to reduce optimizer state. Projection rank/update cadence introduce different optimization semantics; it is not mathematically identical to unprojected Adam. | [Apache-2.0 LICENSE](https://raw.githubusercontent.com/jiaweizzhao/GaLore/master/LICENSE) read. No adapter installed. Projection/SVD overhead, state residency and convergence must be measured separately before combining with block schedules. |
| LOMO/AdaLomo | [LOMO paper](https://arxiv.org/abs/2306.09782), [authors' repository](https://github.com/OpenLMLab/LOMO). LOMO fuses gradient computation and parameter updates; AdaLomo adds adaptive behavior. | [MIT LICENSE](https://raw.githubusercontent.com/OpenLMLab/LOMO/main/LICENSE) read. No fused hook adapter installed. Immediate updates must not invalidate a later backward/recomputed gradient; global norm clipping and accumulation need explicit whole-step treatment, not per-tensor substitutes. Our deferred update path intentionally does not claim fused-update memory savings. |
| Adam-mini | [Paper](https://arxiv.org/abs/2406.16793), [authors' repository](https://github.com/zyushun/Adam-mini). Reduces second-moment resources using parameter blocks motivated by model structure. Arbitrary layer boundaries are not a justified replacement for that partition. | [setup.py](https://raw.githubusercontent.com/zyushun/Adam-mini/main/setup.py) declares MIT and package 1.1.1, but standalone LICENSE fetch returned 404. Exact license text/revision/dependencies remain unresolved for redistribution; do not vendor yet. No local compatibility or memory measurement. |
| LoRA | [Paper](https://arxiv.org/abs/2106.09685), [Microsoft implementation](https://github.com/microsoft/LoRA). Freeze base weights and learn low-rank updates. | [MIT license](https://raw.githubusercontent.com/microsoft/LoRA/main/LICENSE.md) read; no code copied. Local `LoRALinear` implements a dense frozen base plus scaled BA, tested for unchanged initial output, frozen base and adapter gradients. It is not DoRA, QLoRA or an architecture-complete PEFT integration. |
| QLoRA | [Paper](https://arxiv.org/abs/2305.14314). Backpropagates through a frozen 4-bit base into adapters, with NF4/double quantization/paged-optimizer techniques. | No 4-bit backend installed or verified. Never label full-precision LoRA or rounded/dequantized tensors as QLoRA. Paper data/evaluation practices are not adopted; OpenAI-derived datasets/signals remain prohibited here. |
| Activation recomputation | [PyTorch checkpoint documentation](https://docs.pytorch.org/docs/stable/checkpoint.html). Non-reentrant checkpointing and RNG preservation provide concrete APIs, with behavior dependent on stochastic/device state. | Installed PyTorch API exercised only on CPU. Replay covers torch CPU RNG and admitted stateless layers; mutable buffers/custom random sources rejected. Extra forwards/backwards cost time. Parameter/gradient/optimizer CPU memory is still retained. |
| ZeRO-Infinity | [Paper](https://arxiv.org/abs/2104.07857). Uses GPU/CPU/NVMe hierarchy to scale beyond GPU memory. | No adapter/runtime installed or license closure established here. Hardware, bandwidth and dependencies of paper experiments cannot establish practical performance on this Windows PC. |
| FSDP/offload | [Official documentation](https://docs.pytorch.org/docs/stable/fsdp). Shards state and optionally offloads; documented FSDP1 CPU-offload accumulation restrictions matter. | No distributed process group or GPU operation created. Validate the exact FSDP generation/configuration before integration; do not assume all accumulation/offload modes compose. |

No automatic combination is enabled. Block coordinate updates, low-rank projection, reduced second moments, fused updates and quantized frozen weights each change assumptions or resource costs. Proposed combinations need a separate small correctness test and matched-token quality/throughput comparison. CPU/NVMe offload may move the bottleneck rather than remove it. Prefetch increases resident memory; immediate gradient disposal conflicts with global clipping unless a valid additional pass or retained aggregate is used.

## Next experiments, conditional on supervisor admission

1. Keep conventional SGD/Adam and full-precision LoRA as reference paths. Independently licensed real data must be admitted by custody before any actual model-training experiment; the arithmetic software fixtures must never be used for that purpose.
2. Add one version-pinned external optimizer at a time, with complete license/source closure, explicit model block mapping and matched numerical/schedule tests. An unresolved notice is a blocker for that adapter, not for independent work.
3. Extend one device/offload strategy only after CPU equivalence and resource-policy tests. Measure both activation/gradient/state memory and wall time/transfer cost; preserve failures and candidates. No V100 workload now.
4. Compare equal token budgets and held-out quality against the conventional reference before scaling. No 1.0–1.5 GPU VRAM ratio, convergence improvement or Flash/27B practicality is established by this prototype.

Tests use one CPU compute thread and tiny float64 arrays.
