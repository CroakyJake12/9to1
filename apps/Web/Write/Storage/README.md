This repository implements the existing eight `INotesRepository` operations over this browser origin's IndexedDB. It uses actual `NotesDocument`, `NotesDocumentValidator`, `NotesTextStatistics`, `NotesDocumentSearch`, `NotesSaveResult`, `NotesVersionInfo`, and `NotesRevisionConflictException`; it defines no alternate document, account, ACL or remote service model.

Root composition must register `createNotesModule()` from `Services/notes-indexeddb.js` as JS import module `nineToOneNotes`, then inject `new IndexedDbNotesRepository(new BrowserNotesTransport(), new NotesDocumentValidator())` into the existing Write session. The module/repository have device-local lifetime. Store identifiers and receipts are explicitly `indexeddb://nine-to-one-write/...`; they are not filesystem paths or cross-device locations. Origin storage can be cleared or evicted by the browser; no cloud synchronization or provider durability is claimed.

Full canonical document and typed version/receipt JSON are opaque strings in JavaScript. Revisions crossing the IndexedDB index/CAS boundary are decimal strings, compared exactly with BigInt, preserving the canonical signed long range. C# validates incoming and stored content and SHA256 before use; current document and history commit together in a strict IndexedDB readwrite transaction. A receipt requires transaction completion, never request success. A stale revision or changed current record aborts both writes. Mutations are never retried automatically. A verified commit followed by cancellation remains a committed receipt with `PostCommitWarning`; missing/malformed mutation acknowledgment reports `NotesCommitOutcomeUnknownException` and requires durable version inspection before retry.

Delete atomically moves exact current/history records into this-origin trash and removes active records. The existing interface has no trash restore operation; no new product action is invented. Invalid history is never promoted; current corruption can recover the latest validated historical document with actual canonical recovery fields/revision. Recovery does not rewrite current. Saving recovery follows the maintained repository: CAS uses the validated recovered canonical version, while an exact raw-current fingerprint fences replacement against any concurrent change. The corrupt original is retained in trash atomically before replacement. No current document is overwritten without a valid recovery copy. History is retained until deletion; no retention cap or attachment persistence is claimed here.

`Tests/BrowserNotes.Storage.Tests.csproj` runs canonical repository controls over scripted platform transport and generates full actual validator-approved documents for the browser harness with `--fixtures /absolute/output.json`. Those units do not prove IndexedDB persistence. `Tests/indexeddb-browser.mjs /absolute/fixtures.json /absolute/evidence-folder` runs actual Chromium IndexedDB transaction, restart with persistent profile, two-tab CAS, native history constraint abort, real origin quota denial, cancellation, open/disposal and retained trash controls. It uses the root-allocated isolated loopback port 18763; execution requires the resource gate. Those browser adapter controls do not prove WASM interop, retained Write scene/UI, attachments, native package export, account permission or provider acceptance.

The library takes a readonly current/history snapshot and derives summaries through actual validation/recovery, including history-only roots. Read/inspection operations wait for prior mutations in the same module to settle, including their pre-transaction hash/open phase; cancellation can interrupt that wait without cancelling another request. Cross-tab writes retain atomic IndexedDB CAS. Unknown Save exceptions carry the canonical document ID, expected/intended versions, content hash and native version ID for explicit inspection; those are operation evidence, never permission or a new revision authority.
