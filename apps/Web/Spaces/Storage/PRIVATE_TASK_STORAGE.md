# Browser private Task storage composition

`BrowserFeatureComposition` enrolls one `BrowserPrivateTaskStorage` through the
actual registry's non-route private lifetime boundary before its account view
factory. `BrowserPrivateTaskStorageEnrollment` discovers only that same owner
through a weak key of the actual registry. A revoked owner cannot become current
again; replacement waits for the registry's same reset/drain ledger. Enrollment
opens no API, IndexedDB database, provider or model, and exposes no page route.

Explicit storage use creates the existing verified Task actor source and the
current canonical Task/conversation/context adapters. The actor is obtained from
maintained signature verification and current account/profile APIs. Its epoch is
a private broker activation observation, not a fabricated server authorization
revision. Original actor→storage→actor drivers and actual acknowledged commits
remain owned through retirement. A stale activation cannot publish a current
context receipt; a context insert acknowledged immediately before retirement is
retained as a detached original record/actor observation for inspection before
retry. It is not an issued context, no-effect witness or new Task/Run.

The JavaScript host issues a separate correlation owner for each actual native
transport. A transport's invoke, cancel and dispose always name that same owner.
Retirement synchronously fences native admission before callbacks; actual close
then joins owned raw operations, module cleanup and all original causes. An old
owner cannot close a replacement module. Terminal host shutdown fences every
owner before the first module callback and joins all issued drains. Custody is
finite: at most 128 lifetime owners and 256 retained request frames per owner;
successful request frames may be removed only after terminal settlement, while
failed owners/frames retain their original causes until reload.

This is authenticated device-local persistence. It does not register a model,
Home/OS principal, Dev workspace authority, Cloudflare action, canonical Task
admission or permission. This owner now privately constructs the actual durable
event adapter, genuine `ExecutionEventHub` and the preserved three-argument
`TaskExecutionCoordinator`. Its public read facade exposes only Get/GetByContext
of stored work. Canonical execution still requires original admission/runtime/
tool/checkpoint/permission owners and a lawful original-profile live event issuer.
Ordinary coordinator telemetry supplies none of those authorities. Actual
contracts must be tested; no no-op sink or invented Available provider is used.

The original nine source-linked JS host controls plus six guard52E cases use
controlled raw module Promises and faults to test custody, not fake IndexedDB or

Ten additive native source controls drive the actual coordinator, canonical

The additive event persistence adapter implements the actual shared
`IExecutionEventRepository`. Its transport factory uses this same owner's
maintained `BrowserTaskActorSource` and full actor→storage→actor driver. The
canonical event JSON includes every Task/Execution/action/retry/recovery/

The existing database advances to schema3 in the real IndexedDB versionchange
transaction. Schema1 rows are preserved verbatim in their original store and
the maintained schema1 backup. Schema2 takes an atomic complete-key/value backup
of every prior store, including the earlier backup and unknown stores; the
transaction verifies source/copy/backup counts before committing. No original
store or row is deleted or rewritten. Failed copy/open/abort/close retains its
actual cause and leaves the original version/bytes conserved when upgrade aborts.

`ExecutionEvents.Append` uses one actual append transaction. Each profile has
its own canonical positive decimal Int64 sequence with 19-digit padded ordering;
neither JS Number nor autoIncrement stores this sequence. Identical EventId and
complete bytes conserve the original row/order. A conflicting payload aborts the
whole append transaction and conserves original bytes. A receipt follows only
actual oncomplete. Malformed acknowledgements, lost original replies and raw
faults never authorize automatic mutation replay. A complete platform refusal,
including a reported late commit, remains a detached unvalidated original reply
for inspection; it is not a validated append/current actor receipt.

Execution reads validate full payload/hash/profile/link/sequence metadata. Search
derives the maintained native summary algorithm from actual current-profile
rows: trimmed query and SQLite ASCII-folding LIKE semantics; matching-event
group extrema/counts and MAX(sequence) candidate selection before limit; first
prompt/origin and latest full event from the whole execution; then updated
roundtrip timestamp text order. Negative limit returns all and zero returns none.
Timestamp comparisons retain seven-digit fractions and original offsets. Native
ties have no specified order; this adapter uses matching MAX(sequence) as its
deterministic secondary timestamp tie. Corrupt profile rows refuse rather than
being silently omitted.

Only two precise pre-storage transport dispositions can finish without making
private cleanup sticky: a genuinely cancelled same driver/source Task after
lawful original cleanup, or one successfully null verified-actor result before
storage acquisition after its same cancel/release operation finished. The exact
Task states, original cause and actor source Tasks remain in finite owner custody.
Faulted OCE groups, siblings, malformed actor data, private revocation faults,
post-storage identity changes, unknown/late writes and cleanup failures remain
real faults. This does not waive cancellation or refusal after storage entry.
