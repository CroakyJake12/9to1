# Forms browser owner adapter

This surface uses the original `FormsCuiWorkspace`, original embedded `HavenOS.Forms.UI.FormsWorkspace.cui`, `FormAuthoringService`, `FormPublicationService`, `FormProjectCodec` and issuer-created `FormHostSession`. It does not create a second Form model or storage format. The project consumption closure is the unchanged `9to1 Workspace/Forms/CUI/HavenOS.Forms.csproj`, which already references the actual shared Application and CUI Runtime projects.

The host supplies a factory returning a real owner-issued `FormHostSession` and a presentation freshness fence. The latter only suppresses stale presentation; actual actor, StoreID, ownership, revisions and final guarded compare/exchange admission remain the canonical services' responsibility. A null factory returns `HomeServiceUnavailable`. The browser must not instantiate native Home, the local settings provider, or `FormLocalStoreAuthority` to impersonate a remote account. No Forms HTTP, public submission, response, publication or account contract is guessed here. Publish/Close-publication/Respond/NewResponse remain disabled.

`FormsBrowserRoute` opens canonical FormIDs, refuses unsupported navigation contexts, retains the inspector across surface detachment, and commits a prepared owner only after the original CUI loads and presentation admission succeeds. Cancellation/rejection releases only an unconsumed candidate. The close participant rejects destructive closure while the original workspace has inspector drafts or a mutation has an uncertain result. An uncertain save blocks another write until the user opens actual saved owner state and explicitly discards any retained inspector; it does not invent an operation key or retry. An uncertain creation without a returned FormID requires an owner recovery contract.

The route cannot currently register as a private context: `BrowserSurfaceRegistry.Register` rejects private owners implementing `IBrowserCloseParticipant` until the shared shell supports awaited private-context teardown. Root owns that integration. Do not relabel authenticated private forms as `DeviceLocal` to bypass this gate. Actual browser storage, current-account commit authority, publication/response transports and browser rendering acceptance remain separate unverified dependencies.

The pinned [owner contract request](OWNER-CONTRACT-REQUEST.json) separates ordinary save-before-close from revocation. The actual `FormHostSession.Dispose` synchronously fences its captured actor/root, and actual native commit admission checks the session-bound actor again. Sign-out or revocation must invoke that fence and detach private presentation before awaiting cleanup; unsaved inspector state cannot veto revocation or grant a cleanup save. An already committed write may still have an uncertain reply. The current route does not yet track and drain every opening factory/owner command, and the original workspace offers no durable private-inspector recovery port. Maintained owner services must provide those guarantees before private browser registration; the request preserves these gaps explicitly.

The custom executable in `Tests/FormsBrowser.Tests.csproj` references the real Forms/Home projects and source-links the unchanged `FormLocalStoreAuthority.cs` only for native fixture execution. Its explicit physical root backs the actual native provider; it grants no browser filesystem authority. The fixture uses the actual OS principal, actual Home ownership binding, stable provider StoreID, and actual guarded durable settings commits. Negative controls revoke Home ownership, replace the backing store identity, and discard one reply after a successful real commit. It does not supply fabricated private actor grants. The suite plans 13 cases, including independent seed/verify processes and full publication/schema/revision/identity/content oracles. It must be run as an executable, not `dotnet test`, after the SDK gate is granted.

This vertical covers the existing designer's supported text/choice/table/page operations and author preview. It does not assert completion of the full Forms specification, advanced math/graph components, Data transactions, imported themes, collaboration, public submission, sharing, accessibility or platform parity.
