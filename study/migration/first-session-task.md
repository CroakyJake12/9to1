# Optional first 9to1 readiness check (same OpenCode conversation)

While the student works through programming diagnostics, perform the following **only when the existing 9to1 coordinator can admit a bounded background tool job without stopping, reconfiguring or competing with Strata**. If it cannot, do this between tutoring answers rather than falsely asserting background work.

Task: read-only native Boards readiness audit. Observe current checkout identity, uncommitted local edits and active leases/coordinator ownership before any work. Check whether Boards can currently (a) create a recoverable local draft without a cloud account, (b) choose a destination / Save As, (c) save and reopen rich content, (d) display and edit equations, and (e) expose a supported typed tool integration to the active model. Inspect the actual existing tests and any *real* native runtime evidence, and rank the smallest blocking defect preventing one student from writing and reopening a Maths question.

Do not spawn another model, new OpenCode conversation or secondary coordinator. Do not compile or modify source in this first read-only check. Do not call a green unit test an on-screen passing experience. Preserve existing profile, local board files and uncommitted work.

Return a 5-line report when ready: current commit, what was inspected, proven working, unproven/blocked, exact next source/test action. Then continue tutoring without a context switch.
