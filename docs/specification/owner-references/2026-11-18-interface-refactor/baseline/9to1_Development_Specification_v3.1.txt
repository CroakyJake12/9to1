Current layouts and implementation contracts
Version 3.1   1 November 2026   |   Baseline: v3, 28 October 2026
This specification defines the current 9to1 interface and the behaviour that implements it. Each module begins with the foundations it depends on, then describes its layout, features, data ownership, permission boundaries and acceptance checks. The exact mock-ups follow the module they implement.
Use the contents links or Word navigation pane to open a single module. Copy from that module heading to the next module heading when handing work to an implementation model. The companion module pack also provides a separate current Markdown file and a complete technical file for each module.
Current owner decisions control the visual specification. Only source presentation slides 1 through 16 are authoritative. The approved older Study concept remains a behaviour reference inside the current wrapper. Later presentation designs do not define the current interface.
The HTML atlas and these images share the same authored layout source. Desktop references are 1440 by 900 logical pixels; mobile references are 390 by 844. The figures retain their exact proportions. Use the atlas or original PNGs for full-size geometry and theme inspection.
Mock-ups are illustrative, not product acceptance. Boards controls and theme-reference guidance are updated by the v3.1 amendment at the end. Unrelated baseline and retained technical contracts remain active.

Current decisions
Current owner decisions take precedence within their scope. The v3.1 amendment at the end updates Boards controls and the next theme pass; unrelated technical and data contracts remain active.
V3-OWNER-001 Visual authority and implementation scope
Latest owner directions and this v3 module pack control. Presentation slides 1–16 are authoritative. Later slides are historical inspiration; the older Study concept remains an approved rough layout/behaviour reference with the current wrapper. Mock-ups define design intent, not product-verification status.
V3-OWNER-002 Global Assistants and Specialists
Assistants and Specialists are global systems accessible from Home and editors. Editor collaborator avatars/pickers expose them in the current artifact context. Spaces retains their conversation views. Persistent identity, Main threads, memory, tools, permissions and durable Task/Runs are shared canonical entities.
V3-OWNER-003 Notifications owns ecosystem activity
Remove Events as a user-facing navigation destination. Notifications owns notification history and typed ecosystem activity. Existing EventID, provenance, audit and deep-link contracts remain valid backend contracts and are not deleted.
V3-OWNER-004 New Tab icon rail
New Tab uses the compact icon rail shown in the current mock-up. Apps, Dashboard, Models and New Tab remain discoverable semantic destinations. This changes navigation presentation, not the canonical Home services or tab identities.
V3-OWNER-005 Eight current themes and specified material treatments
The current themes are Professional, Glow, Playful, Frosted Glass, Bubble, Metallic, Retro and Western, plus Create Theme. Cinematic is legacy compatibility. Bubble uses watery dimensional surfaces and wobble with reduced-motion alternatives; Western uses wood/sepia treatment; Retro uses a monospace treatment. The Professional annex remains normative. Layout topology and authored content do not change with theme.
V3-OWNER-006 Spaces conversation permissions
Spaces uses an icon labelled Conversation permissions. It controls current-conversation context/action scope and cannot widen durable grants. It is distinct from editor AI Read-only/Write and from document Edit/Suggest/View.
V3-OWNER-007 Model discovery alongside local management
Models is a discovery and comparison experience with local installed-model management available as a distinct useful view. Provider identity, capabilities, hardware fit and unknown metadata remain truthful.
V3-OWNER-008 Spaces generative output and execution visibility
Provide typed interactive Generative UI, visible subagent progress/detail, high-level thinking/work summaries, live semantic work in Present and Canvas, and durable generated-file output cards. Open resolves the canonical artifact; Download appears only when verified durable bytes exist. Failed export preserves saved native artifacts. Never expose private internal chain-of-thought.
V3-OWNER-009 Copyable app modules
Each app module is organised as Prerequisites, Overview, Layouts & visible states, Features & behaviour, Canonical entities & persistence, Permissions & recovery, Acceptance checks and Source clause IDs. Modules include the exact current mock-up mapping and named retained technical subchunks.
V3-OWNER-010 Consistent Home identity
Use the house Home icon consistently in app/host navigation; preserve semantic Home targets and current app-specific identity.
V3-OWNER-011 Boards meaningful editing states
Represent page Add/type, page options, insertion-between-blocks, typing/caret, selected blocks, dragging and ink/tool options. Preserve local native editing without a required Files account and independent Edit/View, Locked and Snap semantics.
V3-OWNER-012 Write document layouts
Show Continuous and actual paginated Pages/Book layouts of the same canonical document with correct selection and contextual controls; changing view never creates a duplicate document.
V3-OWNER-013 Present Actions and custom shapes
Provide explicit meaningful Actions and custom-shape creation/editing states within the approved three-tier Present shell, preserving canonical object/action semantics, notes and manipulation.
V3-OWNER-014 Files selection and content padding
Provide comfortable content and selected-row padding so icons, names and metadata do not collide with selection backgrounds or table edges; preserve real file-management density and operations.
V3-OWNER-015 Planner event nib
Planner event cards use a clear colour nib and readable interior padding, while event identity, time/recurrence and state remain authoritative.
V3-OWNER-016 Cards neighbouring offsets
Focused Cards show visibly offset neighbouring cards with clear front/back and Edit versus View semantics; vertical stack is the default and supported horizontal orientation remains available.
V3-OWNER-017 Native emoji
Emoji characters use native platform emoji rendering. Do not substitute text-glyph boxes or custom application icons for emoji; keep coherent app/control icon assets separate.
V3-RECON-001 Confirmed discrete effort mapping supersedes ambiguous percentage mapping
SPUI-133 explicitly supersedes application of the older arbitrary-percentage floor formula to the visible effort presets. Visible choices map bijectively to actual provider LevelIDs/ordinals. Any retained arbitrary-percent legacy API must be separately versioned and cannot shift or duplicate the displayed tier choices.
V3-RECON-002 Expired delivery schedules and worker assignments
Historical dated schedules and named worker/session assignments are provenance, not current product requirements or execution authorisation. Compatible product/runtime, packaging, platform, security and acceptance requirements remain active; original process wording is retained in the history ledger.

Platform app registry and host integration
Module platform    Current contract and exact reference designs
Prerequisites
Authority, scope and implementation reading map. Current source precedence, narrow owner overrides, source accounting and the required module structure.
Overview
The ecosystem shares canonical applications, artifacts and services across native, browser, mobile and 9to1OS hosts. Host presentation may differ while object identity, permissions and typed actions remain the same.
Current overrides: V3-OWNER-010.
Layouts and visible states
V3-PLATFORM-LAY-01  Expose authentic app launch/create/open/import/recents surfaces separately from active editor workspaces. A launch page must not remain as a decorative dashboard above an open document.
V3-PLATFORM-LAY-02  Keep a familiar Home house icon in app headers. Respect host-safe top regions, viewport insets and narrow-screen drawer behaviour.
V3-PLATFORM-LAY-03  Distinguish installed, available, offline, unsupported, starting, ready and failed states; do not make a static tile imply a working runtime.
Features and behaviour
V3-PLATFORM-FEA-01  Register app capabilities and routes once; Home, Browse, OS and Launcher use that registry. Opening an artifact resolves its registered owner and stable target, including embedded AppSurfaces.
V3-PLATFORM-FEA-02  Offer manual local editing without requiring sign-in, a connected Files provider or a running AI service unless the underlying operation itself needs it.
V3-PLATFORM-FEA-03  Preserve the retained platform/backend language, donor reuse and UI/API parity requirements. CUI wraps existing powerful engines rather than replacing them with a reduced demonstration.
V3-PLATFORM-FEA-04  Integrate typed creation, selection, edits, exports, task events and deep links. Automation uses these semantic APIs, not simulated pointer interaction.
V3-PLATFORM-FEA-05  Native documents/projects must not impose arbitrary global character, word, page, slide, block, object or file-byte caps merely to simplify rendering or saves. Real device, quota, format, address-space and security limits remain explicit; never truncate silently.
V3-PLATFORM-FEA-06  Prioritise current input, caret, selection, scroll, drag and undo over distant work. Virtualise visible/nearby pages, slides, cells, blocks, nodes and time ranges, use indexed deep navigation and bounded adaptive caches, and keep unrendered content canonical, searchable, accessible and exportable.
V3-PLATFORM-FEA-07  Use incremental dependency-aware layout/calculation and addressable/chunked persistence; do not reserialise or rerender an entire large artifact on each keystroke. Stream/resume/cancel large import/export with integrity checks, honest progress and safe resource-pressure recovery. Lower preview fidelity or buffers before document fidelity.
Canonical entities and persistence
V3-PLATFORM-ENT-01  Keep stable AppID, artifact ID, TabID, route, revision and request identities. Do not duplicate documents when moving between native, embedded and browser views.
V3-PLATFORM-ENT-02  Draft, active configuration, current view state and published output are separate records. Closing a view does not implicitly cancel an admitted background Task/Run.
Permissions and recovery
V3-PLATFORM-PER-01  Check permissions at execution and dereference time, including cached/search and embedded surfaces. Explicitly distinguish unavailable capabilities from denied permissions.
V3-PLATFORM-PER-02  Preserve unsaved work through host navigation, process restart and session restore; Save/Discard/Cancel must refer to actual dirty state.
Acceptance checks
V3-PLATFORM-ACC-01  Open the same artifact through Home, Files, a host tab and a Space; verify stable identity, current revision and consistent grants.
V3-PLATFORM-ACC-02  Test app launch→create/open→edit→save→reopen, narrow layout, offline recovery and unsupported-platform states.

CUI themes and shared interaction system
Module cui    Current contract and exact reference designs
Prerequisites
Authority, scope and implementation reading map. Current source precedence, narrow owner overrides, source accounting and the required module structure.
Overview
CUI is the single public UI system for every 9to1 surface. The current Professional annex defines the canonical restrained default; theme identity changes materials, typography and motion without changing app topology or repainting authored content.
Current overrides: V3-OWNER-001, V3-OWNER-005, V3-OWNER-010, V3-OWNER-017.
Layouts and visible states
V3-CUI-LAY-01  Offer Professional, Glow, Playful, Frosted Glass, Bubble, Metallic, Retro and Western, plus Create Theme. Cinematic is an explicit legacy compatibility choice rather than a ninth current default.
V3-CUI-LAY-02  Preserve each theme’s character: Professional restrained dark charcoal; Glow luminous accent-dependent controls; Playful soft coloured surfaces; Frosted Glass translucent layered material with a legible fallback; Bubble watery dimensional surfaces and gentle wobble; Metallic brushed reflective material; Retro monospace; Western wood and sepia.
V3-CUI-LAY-03  Use Montserrat by default except the explicit Retro monospace treatment or authored document fonts. Use the exact Professional annex tokens, geometry and states where specified rather than inventing near-equivalent colours.
V3-CUI-LAY-04  Show normal, hover, pressed, selected, disabled, focused, loading, validation, destructive and reduced-motion states. Icon and text contrast must remain legible over every theme material.
V3-CUI-LAY-05  Use native platform emoji rendering for emoji characters. Keep application glyphs and identity marks coherent, distinct from decorative emoji.
Features and behaviour
V3-CUI-FEA-01  Use CUI public primitives and typed templates. Avalonia and donor engines are internal implementation details; do not expose raw AXAML or third-party controls as a competing public UI language.
V3-CUI-FEA-02  Keep one deliberate primary scroll container per workspace, bounded panels and predictable focus/keyboard order. Popovers reposition at viewport edges; Escape/outside dismissal returns focus appropriately.
V3-CUI-FEA-03  Shared menus, tooltips, sliders, switches, inputs, tabbars, avatars, toasts, dialog surfaces and selection controls inherit the same theme and semantic action variants.
V3-CUI-FEA-04  App-specific content retains its own colours: slides, pages, photographs, charts, canvases and web previews do not receive theme-tint filters.
V3-CUI-FEA-05  Reduced motion disables wobble, bounce and ornamental animation while preserving state changes and feedback. Transparency and material effects need performant, accessible fallback modes.
Canonical entities and persistence
V3-CUI-ENT-01  Store theme identity/version, compatible custom tokens, accent, typography/density and accessibility preferences in the Home-owned account/device preference contract. Space-specific overrides are explicit and reversible.
V3-CUI-ENT-02  Keep semantic tokens separate from app identity accents and document content. Theme switching must not mutate artifact revision or user-authored styles.
Permissions and recovery
V3-CUI-PER-01  Custom themes are validated against supported tokens and accessible contrast/focus requirements; importing one is not permission to execute arbitrary UI code.
V3-CUI-PER-02  Restore a valid baseline if a theme resource is missing, incompatible or fails to load; preserve the user’s chosen identity for recovery.
Acceptance checks
V3-CUI-ACC-01  Review all eight current themes, a custom theme and Cinematic compatibility with keyboard focus, mixed selected/disabled states, narrow screens and reduced motion.
V3-CUI-ACC-02  Verify the Professional annex’s menu/toolbar/selection/notes and Present geometry exactly; compare rendered state captures rather than only token files.
V3-CUI-ACC-03  Change themes while editing and verify selection, drafts, scroll, runtime state and authored content survive unchanged.

Create Theme Authoring and preview
custom-theme    Professional dark    1440 by 900 logical pixels
Exact reference composition from the offline atlas.
Implementation rules
1. Primary, Secondary and Tertiary each independently choose Solid Colour, Gradient or Pattern, with authored transparency and supported blur.
2. All seven font roles expose family, weight and size. Button Roundness accepts the full 0–100% range.
3. This custom theme inherits Professional, so supported backdrop blur can be authored. Preview does not modify the saved preference until Save.
4. An app override recolours only Primary, preserving gradient stops, pattern geometry, transparency and blur; Secondary/Tertiary remain authored.
5. Hover Effects and Custom Cursors are later enhancements and are not presented as enabled controls.
Source: CUI-PREF-204–205; CUI-PRO-203; CUI inherited themes and typed fallback
Components Buttons inputs and control states
components    Professional dark    1440 by 900 logical pixels
Exact reference composition from the offline atlas.
Implementation rules
1. Primary, Secondary, Tertiary, Negative and Text buttons retain their semantic hierarchy in Professional and Glow. Accent-dependent colours resolve through the selected theme.
2. Hover morphs, pressed feedback and focus are distinct. The slide’s bounce becomes a restrained interruptible press response; reduced motion removes movement.
3. Five-second destructive hold is one optional pointer path. A keyboard/single-activation review dialog provides an equally explicit accessible confirmation route.
4. Input focus, invalid and disabled states remain distinct. Active controls never inherit disabled parent opacity.
5. Shared Feedback/Reveal/Reflow/Panel durations are 100/140/180/220 ms draft defaults; input, caret, save truth and permissions do not wait for animation.
6. Professional/Glow component examples preserve the deck’s blue/orange palette. Dark labels on bright Glow/red hover fills retain contrast. The six other themes are new design definitions; Professional material always has an opaque fallback.
Source: Authoritative PPT slides 1–6; UX27-SHARED-002–008/019; CUI-THEME-004
Bubble Material and controls
theme-bubble    Bubble dark    1440 by 900 logical pixels
Exact reference composition from the offline atlas.
Implementation rules
1. Water-like highlights and refracted edge light give controls depth. Gloss is restricted to control surfaces; text retains stable contrast and authored paper colours stay unchanged.
2. A click applies one 520 ms damped wobble to the activated control. State and action feedback occur immediately; animation never delays execution, save or permission changes.
3. Reduced Motion and the operating-system preference both remove movement. There is no ambient loop, floating layout or full-screen blur.
4. Light mode uses pale water surfaces and dark teal text. High contrast omits material decoration; focus and selected states remain separately visible.
5. The sample document is authored content: its cream paper, type and ink remain identical under every theme. Theme selection does not edit the document or grant any tool permission.
Source: Owner theme refinement, 28 October 2026; CUI-PREF-201–205; CUI-THEME-001–004; Retro category reference: https://opencode.ai/docs/themes/

Retro Material and controls
theme-retro    Retro dark    1440 by 900 logical pixels

Implementation rules
1. Modern terminal conventions inform the charcoal panels, monochrome hierarchy, monospace chrome, sharp control cells and hard offset shadows. OpenCode’s public theme documentation is a category reference, not a product or branding copy.

4. App accents and semantic status colours remain distinct. Light mode uses a legible paper-terminal palette; themes retain the same toolbar/container geometry.
5. The sample document is authored content: its cream paper, type and ink remain identical under every theme. Theme selection does not edit the document or grant any tool permission.

Features and behaviour
V3-SPACES-FEA-01  Submit only after admission succeeds; keep the draft when validation/admission fails. Steer affects future work, Queue preserves the queued message, and Stop reports actual stop acknowledgement rather than rewriting past outputs.
V3-SPACES-FEA-02  Respect per-Space default Steer/Queue policy and Alt+Enter inversion where the companion specifies it. A queued message must not be silently interpreted as a retroactive edit or immediate tool invocation.
V3-SPACES-FEA-03  Resolve +, @ and slash commands through canonical registered resource/invocation inventories. Passive mentions are references; explicit bounded commands execute only through real permission-aware APIs. Rich formatting and per-message Canvas composition preserve original message history.
V3-SPACES-FEA-04  Model effort labels bind directly to supported provider level IDs; they are neither quota nor confidence. Separate context and provider usage metrics, show unknown values honestly and hide inapplicable cloud allowance for local routes.
V3-SPACES-FEA-05  Chat Type and Chat Location are independent dimensions. Types are Normal, Multi-Agent and Temporary; locations are Local, Mesh and Cloud. Model execution location is separately governed from conversation storage.
V3-SPACES-FEA-06  Support approved conversions Temporary→Normal, Temporary→Multi-Agent and Normal→Multi-Agent without replaying tools or fabricating past participant replies. Temporary first becomes a durable local chat; Mesh/Cloud promotion is a separate authorised action. Unapproved reverse conversions are not silently added.
V3-SPACES-FEA-07  Chat Groups contains Group and Project organisation containers, not multi-agent chats and not new Spaces. Both reference canonical member conversations; Group adds shared instructions/relevant authorised context; Project additionally adds Sources, Rules and local/server/remote/cloud resource connections.
V3-SPACES-FEA-08  Group→Project is a one-way supported conversion preserving identity/history/members where safe; Project→Group is rejected. Removing a container does not silently delete its member chats.
V3-SPACES-FEA-09  Tasks defaults to the user’s own relevant task scope with explicit All Tasks filtering. Show objective, plan, steps, dependencies, blockers, approvals, source/outputs, real state and canonical task badges with accessible detail.
V3-SPACES-FEA-10  Study provides dashboard→subjects→subject/topics, source-backed tutor/practice and recorded progress. Revision Bank exposes Recommended, All, Flashcards, Notes, Papers and Quizzes, using Cards and Forms canonical artifacts. The older concept is a rough approved behaviour/layout reference under the current wrapper.
V3-SPACES-FEA-11  Assistant views open the global system’s permanent Main thread, additional conversations, Teams and work. Specialists launch the correct owned/available configured identity. These views do not replace Home/editor access to the global systems.
V3-SPACES-FEA-12  Research moves from initial conversation to reviewable plan, scope, sources and selected deliverables before Start. Quick/Extended/Deep/Custom modes use actual supported budgets; active execution time excludes waiting/paused periods and is not a completion guarantee.
V3-SPACES-FEA-13  Shopping combines natural-language control and conventional filters, distinguishes Required from Preferred constraints and exposes strict matches, alternatives/near matches and contextual recommendations with explicit reasons. Keep products separate from merchant offers, currency/price/freshness/source provenance visible, and purchase actions external and authorised.
V3-SPACES-FEA-14  Translate keeps language chips above the standard composer and one response bubble per target language, linked as sibling outputs in a TranslationSet. Route through real translation/model capabilities.
V3-SPACES-FEA-15  Experiences owns persistent world/scene, character, inventory, evidence, objectives, flags, checkpoints and branching state. Commit validated canonical state before narrating its outcome, enforce hidden-state visibility and retain recoverable checkpoints. Formal competition remains Play’s domain.
V3-SPACES-FEA-16  Basic configures name, description, icon, instructions, supported category availability and resources. Advanced adds Mandatory/Allowed/Blocked/Inherited capabilities, memory, genuine model parameters, Assistant/Specialist defaults, canonical Automations, theme/sidebar/message-control overrides and prompts.
V3-SPACES-FEA-17  Expert reuses the Home-owned Node Editor. Harness Logic configures permitted lifecycle/composer/sidebar/GenUI behaviour; Model Logic configures authorised routes/prompts/parameters; User Message Logic operates on derived representations without rewriting the immutable original message; Files is a real nested resource system.
V3-SPACES-FEA-18  Switching Builder tabs must preserve Expert-only nodes/behaviour and show Expert configurations active where simplified views cannot express it. Preview, Validate and Activate/Create are distinct; invalid drafts never replace the valid active graph. Templates and AI-assisted edits are inspectable starter changes, not implicit installed connections or automatic publication.
V3-SPACES-FEA-19  Typed GenUI is safely schema-bound and stateful. Open in App retains canonical identity. Live artifact work uses the owning app’s semantic edit APIs and any required review/approval rather than raw pointer simulation.
V3-SPACES-FEA-20  Subagent activity exposes delegation objective, current state, scope, blockers, outputs and high-level work events. Useful thinking summaries may show observed steps/tools/evidence but never private internal reasoning.
V3-SPACES-FEA-21  Study proficiency uses the four explicit labels Not assessed (neutral), Needs work (red), Developing (amber) and Confident (green), backed by attributable attempts and documented rules. Keep self-reported confidence separate from demonstrated proficiency; opening a lesson or flipping a card is not mastery evidence. Revise These ranks at most three distinct topics across all subjects using weak-first, then overdue/oldest-reviewed and stable TopicID ties, with an intelligible reason; unassessed is not weak.
V3-SPACES-FEA-22  Learn provides guided explanation; Practise records actual answers/working, hints and feedback; Test uses canonical Forms assessments with rubric/timing/provenance; Review uses recorded due/weak topics and Cards attempts. My sources only enforces the configured closed corpus and never fabricates citations. Permissions and recovery
V3-SPACES-PER-01  Conversation permissions narrow current use within durable grants; they cannot elevate app/org policy. Every consequential action still requires its applicable action approval, even if a category is available.
V3-SPACES-PER-02  Voice toggle never silently enables camera/screen sharing. Persistent indicators reflect actual capture; Stop sharing must stop frames reaching the runtime. Open in Vision & Voice preserves the same session.
V3-SPACES-PER-03  Group/Project sharing, multi-agent participation and context retrieval preserve provenance and participant/source permissions. Do not assume detailed turn-taking/human participation policy from the mere presence of a Multi-Agent label where source decisions remain open.
V3-SPACES-PER-04  Builder validates mandatory-but-blocked conflicts, unavailable dependencies, typed ports, cycles/budgets, model capability, CUI safety and effective policy. Imported Skills/Plugins/MCP/models/mini apps are validated through their owners, never auto-trusted by folder membership.
V3-SPACES-PER-05  An invalid generated component preserves prior valid content and offers repair. A failed PDF/export preserves the saved native artifact and retries only that export from the selected revision; repeated retry must not duplicate earlier external effects.
V3-SPACES-PER-06  Tab close/back respects dirty state and preserves background runs. Revoked resources are redacted from cached display/retrieval; unavailable contexts show recoverable state without discarding drafts.
V3-SPACES-PER-07  Peer Review limits count aggregate reviewer active time against measured productive worker active time, not wall-clock waiting or duplicated simultaneous worker clocks. Exhaustion never bypasses a required permission/review gate.
