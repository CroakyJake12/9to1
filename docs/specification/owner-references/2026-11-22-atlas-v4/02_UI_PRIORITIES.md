# 9to1 — visible implementation priorities

## Working order

**First hour: Astra is the rapid implementer.** Bring up the actual app, compare it with the supplied Atlas, and personally deliver visible, coherent interface improvements. Keep discovery short and make the first visible increment early. Backend work belongs in this hour only when it directly blocks launching or exercising the chosen interface. A plan, a token refactor, an unchanged preview or an edited mockup alone is not a visible product result.

**After the first hour: Astra carefully coordinates and reviews rapid implementers.** Continue the same visible UI programme through bounded, non-overlapping work packages. The separate speed-optimisation chat owns Qwen 3.8 setup and will supply its tested handoff. No initial Qwen worker, endpoint, throughput, concurrency or context limit is assumed here. Do not duplicate that investigation or interrupt it to tune inference.

The first-hour goal is a working, visibly improved desktop shell plus a coherent Chat/Options or Appearance slice, with a short before/after demonstration in the actual app. The full 282-route Atlas is the design reference, not a requirement to recreate every route in an hour. At each checkpoint, show the running result, identify what works, and name the next visible change. Preserve existing behaviour while improving its presentation.
