## 7.1 Files and Flow

APP-FILES-001 — Files retains address/breadcrumb/history, search, selection, sorting, List/Grid and details. Both views address the same folder/selection. Provider-native create/open/import, rename, move, copy, trash/restore and metadata return actual receipts. Move preserves identity; Copy creates a declared new artifact. Collisions offer applicable Replace, Keep both and Skip choices, with per-item bulk outcomes. Local availability and provider sync differ; cloud outage does not block local folders.

APP-FILES-002 — Open/Open with resolves the owning app and current permissions. A .9to1board remains the same editable Board. Denied, empty, missing, disconnected and unsupported-preview states are distinguishable without leaking inaccessible metadata. Selection tint/padding surrounds complete rows or tiles; the selected entity remains clear after menus close. Trash is recoverable where the provider supports it; unsupported recovery must be disclosed.

APP-FILES-003 — The ten organisation types are Folder, Project, Sheet, Tree, Smart, Timeline, Pipeline, Catalogue, Stash and Matrix. Each retains the standard shell, compatible nesting and ordinary Contents view without erasing specialised metadata. Tree’s visual authoring requires editor rights. Smart queries retain source scope; Pipeline movement respects configured stages/gates; Matrix axes use stable identities. An unimplemented specialised view reports that capability honestly instead of losing its saved state.

APP-FILES-004 — Sheet arranges references, notes, drawings and shapes. Add existing defaults to Add reference; removal does not delete/move its source. Default file opening is Pop-up. In authoring, click selects and explicit Open opens; an owning editor discloses that it edits the original. Geometry/connectors/shared layout/opening policy persist as Sheet content; selection, viewport and view choice are per user. Source permissions remain independent.

APP-LINK-001 — Flow composes inline content in one primary vertical scroll. A report can combine Data regions, Write content, images and a scoped report Assistant, including multiple regions from the same source. Placements retain canonical source/section IDs and explicit live/pinned policies. Move, duplicate placement and remove affect composition only. Edit original checks source permission and restores the same Flow position afterward.

APP-LINK-002 — Binder is one authored interconnected document containing real nested notes, cards, folders, tabs/stacks, sections, connections and shared objects. References preserve originals. Reader mode supports nonlinear opening, breadcrumbs, Back and outline without layout handles. Add/reorder/remove preserves stable container/item IDs. Closing a container or cancelling Insert restores viewport/focus. Missing source, denied access and newer source revision remain visible rather than becoming a silent copy.

Acceptance — Switch List/Grid, move a file without breaking links and reject a collision. Remove a Sheet or Flow placement and reopen the unchanged source. Embed two Data regions under declared revision policies; navigate a Binder container and return with focus/position intact. Check source permission independently of access to the composition.

Atlas anchors: files, files-grid, files-context, files-organisation, link-flow, link-flow-block-edit, link-binder, link-binder-insert.

### 7.1.1 Real file operations and ten organisation types

ED-FILES-001 — Files resolves provider, stable item ID, locator, revision/version token, availability and operation capabilities independently of the selected view. Transfer jobs identify source/destination, copy versus move, progress, conflict choice and actual committed result per item. Cross-provider Move is a recoverable copy/verify/delete sequence rather than an assumed atomic rename; source deletion occurs only after confirmed destination integrity and authorised commit. Interrupted upload/download resumes against matching identity/content where supported. Directory enumeration and search preserve inaccessible/offline distinctions and do not infer an empty folder from a failed listing.

ED-FILES-002 — Every specialised organisation is a versioned Files object with stable membership/placement IDs referencing originals. New item declares a backing destination; adding an appearance defaults to a reference. Nesting supports all ten organisation types where provider capability permits, while owned containment remains acyclic and reference expansion detects recursion. Ordinary Contents view preserves specialised layout. Contextual breadcrumbs identify sections/groups separately from physical directories. Remove appearance and delete original are separately named operations. Source rename/move updates references through identity, not filename matching.

ED-FILES-003 — Folder retains ordinary filesystem behaviour. Project groups appearances into named sections with stable SectionIDs and an Unsectioned area; sections are not subfolders. Sort can target one section or the project explicitly. Removing a section offers reassignment/Unsectioned or removal of appearances, preserving originals. Personal collapse state is separate from shared section order. Deep links survive renaming. Each section’s count reflects permitted displayed membership rather than inaccessible records.

ED-FILES-004 — Sheet owns spatial placements, notes, drawings/shapes, connectors and shared geometry. It references files without merging their content. File-opening policy is Pop-up initially or Owning app; a one-off alternate Open does not change that default. Editing through a safe embedded owner identifies that it edits the original. Sheet geometry undo cannot undo a source edit from a different application. Tree adds explicit groups, hierarchy/connections and layout with cycle rejection. Editors may use Tree/View; viewers receive ordinary View and cannot retrieve protected visual layout through a hidden embed/API route. Tree editing rights do not grant source-file edits.

ED-FILES-005 — Smart stores visible All/Any rules, selected locations, recursion policy and manual pins. Each result explains its match; unavailable metadata is unknown, not false. Pinned non-matches remain labelled. Removing a dynamic match explains that it returns while the rule matches. Offline providers expose stale/partial results. Timeline stores a chosen date source—Created, Modified, Deadline or Assigned—plus local periods/ranges. Dragging Assigned changes local timeline data; moving under a source-derived date requires an explicit owning metadata operation. Undated items remain reachable and all-day/timezone semantics are preserved.

ED-FILES-006 — Pipeline membership owns local StageID, order, checklists and transition/approval history. New personal pipelines have no mandatory gates unless configured. Pointer, command and API transitions enforce the same prerequisites/revision checks. A pending review is not a completed move. Global metadata mapping is explicit and names affected fields/rights/conflict behaviour; stage changes otherwise remain local. Catalogue entries own typed local fields plus explicit source-property mappings. Type conversions preview incompatible values; local notes/rating never alter another catalogue. Removing a field preserves source metadata and supports recovery of its own values.

ED-FILES-007 — Stash stores an authored sequence of separate originals; reading position and optional Reviewed state are personal, keyed to EntryID. Reordering preserves the current item, not a numeric index. Compare selects two independent slots without advancing the main reader; narrow view may switch labelled A/B. Matrix owns stable row/column axes and cell memberships. Axis renames/reorders preserve CellID identity; deletion offers reassignment, Unassigned or appearance removal. Combined row/column views disclose repeated references and count the actual displayed unit. A large Matrix retains readable scrolling/filtering rather than shrinking everything beyond use.

ED-FILES-008 — Workflow A: move a local board, copy it to another provider, introduce a name collision and interrupt transfer; verify source/destination integrity and explicit per-item state. Add the same original to a Project, Sheet and Catalogue, edit it from the Sheet, move one appearance and remove another. Source identity and global edits remain shared while local geometry/notes stay independent. Reopen in ordinary Contents and restore specialised views without lost metadata.

ED-FILES-009 — Workflow B: create Smart rules with a pinned non-match and offline location; inspect inclusion reasons. Use Timeline Assigned and Modified sources and verify dragging does not rewrite Modified. Reject an unmet Pipeline gate, then complete the allowed transition through keyboard. Open Tree as a viewer and verify layout cannot leak. Reorder a Stash during reading and remove a Matrix axis while preserving originals and clear placement context.

### 7.1.2 Flow composition and nested reading

ED-LINK-001 — Flow exposes continuous Flow and nested Binder document types; Sheet remains Files-owned. Flow owns arrangement and directly authored shared objects while source files retain independent ownership. The Sources panel records source/section IDs, live or pinned policy, availability and permissions. Duplicate Flow copies authored structure but retains external references unless independent source copies are explicitly requested. A source replacement validates the selected section/type and reports affected placements rather than silently substituting whatever matches a title. Preserve legacy Link route, package, document-type and schema identifiers as compatible aliases; the navigation name is Flow.

ED-LINK-002 — Flow is an ordered sequence of inline content with one primary vertical reading scroll. Large tables may scroll horizontally and media retain playback controls; normal documents do not become nested vertical scrollboxes. A stable reader anchor identifies the placement and source-content position, enabling refresh or return from the original editor without jumping to the beginning. Reorder/duplicate/remove changes placements only. Live updates preserve position where content survives; pinned blocks remain on their chosen revision. Missing sections, unavailable renderers and revoked sources leave bounded placeholders with repair actions.

ED-LINK-003 — Binder owns nested notes, folders, tabs, stacks, cards, connections and content, not a simulated file-manager hierarchy. Containers and connections use stable IDs, authored geometry and declared open behaviour. Outline commands provide the same navigation/edit operations without spatial precision. Reader mode hides authoring handles but supports nonlinear exploration, Back/breadcrumbs, deep links, search and return to the exact surrounding view. Personal open containers/tab selections remain distinct from author-set starting state. Deleting a container previews owned descendants while leaving referenced originals intact.

ED-LINK-004 — Workflow A: assemble a Flow report from Data, Write, an image, another section of the same Data source and a report-scoped Assistant. Read continuously, update the original, pin one placement, revoke another source and return from its editor. Verify each declared refresh policy and reader anchor without source copying. Workflow B: author a Binder folder, tabbed binder, stack and referenced file; explore out of order, rename/deep-link a nested item and open it from a Files Sheet. Reopen with authored nesting intact and user reading state restored independently.

## 7.2 Planner and Automations

APP-PLANNER-001 — Calendar/task views share canonical Events and PlannerTasks. Scheduling an unscheduled task does not duplicate it. Edit/move/resize shows actual calendar, date, timezone, start/end and reminders. Recurrence edits choose occurrence, following occurrences or series. Burrow membership references the source. Completing a task, dismissing a reminder, removing membership and deleting an event are separate actions.

APP-PLANNER-002 — Category colour is an inset vertical nib with its own radius. Panels collapse before the grid becomes unusable; Agenda is the supported narrow alternative. AI scheduling presents the actual target calendar, times and conflicts before authorised commit. Offline/unavailable calendars preserve proposals and truthful pending states. Keyboard time editing offers a drag alternative.

APP-AUTO-001 — Automations uses canonical typed graphs with stable automation/node IDs, triggers, inputs, conditions, actions, outputs, branches, parallel work, approvals and retry outcomes. Compatible ports are explicit. Draft and Active revisions are visibly different. Save/Test never activates. Validation checks graph types, references, budgets and effective permissions and identifies the offending node/edge without replacing the current active revision.

APP-AUTO-002 — Tests name input, environment, permissions and live/mock status; live external effects retain approval boundaries. Runs pin their starting revision. Durable waits/resume do not replay committed effects. Schedule configuration includes time, timezone, days, daylight-saving handling and missed/offline-run policy. Credentials/tool failure produces a scoped recoverable state. A trigger edit does not dispatch downstream work or silently change the active schedule.

Acceptance — Schedule one existing task, change one recurrence and compare Week/Agenda identity. Save an invalid automation draft without activation; validate/test a corrected revision; activate deliberately. Restart during a durable wait and verify exactly one committed effect. Apply the selected missed-run and timezone policy using actual scheduler evidence.

Atlas anchors: planner, planner-event, planner-agenda, automations, automation-trigger.

### 7.2.1 Planning entities and time semantics

ED-PLANNER-001 — Calendar, PlannerEvent, PlannerTask, Reminder, recurring series/exception, Schedule, Countdown and Assignment are distinct entities. A task can have a due date without a scheduled interval; dragging it into a calendar assigns that same task’s schedule. Removing it from the grid can unschedule without deletion or loss of due date. PlannerTask is distinct from a runtime TaskID in the Actions Space and may link to it when a run creates or reviews planned work. Burrows organise canonical planning references; hiding a module or removing membership does not delete its items.

ED-PLANNER-002 — Timed items distinguish event timezone, absolute instant and viewer timezone; explicitly supported floating local time is another declared mode. All-day spans store dates and do not drift through UTC conversion. Recurrence stores a bounded rule and exceptions rather than precreating infinite copies. An occurrence has series plus recurrence-key identity. This occurrence, this and following, and entire-series edits preserve the appropriate identity/exceptions. Expand only queried/visible intervals. DST ambiguous/nonexistent local times use a visible deterministic policy, and a timezone change previews affected occurrences.

ED-PLANNER-003 — Today/Day/Week/Month/Agenda/Tasks project the same records. Grid selection previews start/end and creates only on commitment; resize respects valid duration and source capability. Overlapping events remain independently selectable; all-day items occupy their own region. Keyboard commands provide date traversal and time edits. Reminders use the shared notification service and distinguish scheduled, fired, snoozed and dismissed. Snooze changes delivery time, never the event’s start or task due date. Occurrence reminders retain occurrence identity.

ED-PLANNER-004 — Optional Schedule contains ordered timed items with references; elapsed/remaining figures derive from the clock and are distinct from an item’s share of the whole day. Countdown owns a target or explicitly follows another event/assignment’s authoritative date. Assignment owns required/optional items, status and completion policy. Required completion, optional extras, manual progress and weighted calculation remain distinguishable; optional items do not prevent completion. An override of incomplete required work is explicit and attributed. An assignee label alone is not an edit grant.

ED-PLANNER-005 — Provider calendars declare read/write, recurrence, attendee, reminder, meeting and sync capabilities. Saving can be local/save-only or notify attendees where supported; external invitations/cancellations are separate effects, not hidden autosave. iCalendar import/export preserves representable UID, timezone, recurrence and exceptions and detects duplicates through stable mappings. Maps-derived departure reminders follow route duration plus explicit buffer without changing the event. Mail extraction retains source reference and reviews uncertain dates. Overdue-triggered communication belongs to an Automation invoking Connect, not a hidden Planner side effect.

ED-PLANNER-006 — Workflow A: create an all-day event, a timezone-aware recurring event and a due-but-unscheduled task. Schedule/unschedule the task, edit one occurrence and the future series, cross a DST transition and switch viewer timezone. Verify canonical IDs, dates, exceptions and reminder boundaries. Workflow B: link a Countdown, Schedule item and Assignment; complete required work, snooze a reminder and import the same calendar twice. Verify no duplicate planning records, no accidental date changes and no message sent merely because work became overdue.

### 7.2.2 Automation definitions and durable execution

ED-AUTO-001 — An Automation owns one graph identity, draft/active revisions, trigger schema, required capabilities and execution policy. Simple When/If/Then and natural-language builders mutate that graph. Node catalogue entries come from actual registered app/device/provider capabilities. Right-click search inserts at a captured graph point; typed port dragging previews compatible targets; Ctrl-click connector deletion, context Delete and keyboard deletion remove the edge alone. Text editing, panning, selection and node movement dispatch separately. Validation annotates exact nodes/edges and preserves the valid active graph.

ED-AUTO-002 — Triggers include manual, schedule, typed app event, condition/watch, supported external event and another Automation. Delivery identity and admission deduplication are explicit. Prefer change events when available; polling declares its cadence and resource cost. Null, false, unavailable/redacted and error remain different branch inputs. Conversion nodes are explicit. Loops require a termination/budget policy; parallel branches declare join conditions and mixed-success handling. An approval node is workflow review and remains distinct from the shared permission broker; either may independently block execution.

ED-AUTO-003 — A run pins its active revision and records triggering event, typed inputs, per-node attempts/results, causal ancestry and durable continuation. Wait releases active execution resources and persists resume conditions; a sleeping UI thread is insufficient. Disabling a definition prevents new starts and separately offers what happens to existing runs. Activation is atomic and does not change a running revision. The executor may be cloud, local or a compatible Mesh device; device-bound work cannot claim execution while its required device is offline.

ED-AUTO-004 — Retry identifies the failed node/attempt and retains successful outputs. Computational retries and consequential actions follow their own idempotency/receipt contracts. Timeouts with uncertain effects pause for reconciliation. Cancellation reports committed work and supported stop boundaries without implying external undo. Sharing a graph includes capability/version requirements but not credentials or the owner’s grants. A new effect such as Draft to Send requires fresh capability-policy evaluation. Device-specific nodes disclose portability and cannot silently substitute another target.

ED-AUTO-005 — Workflow A: create an event-triggered graph with filter, parallel branches, join, approval, app action and durable wait. Save a malformed draft while a previous version remains active; correct and activate. Restart during Wait, receive the same trigger again and verify one admitted run and no replayed effect. Workflow B: change a device-specific action to an unavailable target, inspect Needs Attention, cancel one branch and retry a failed computation. Reconcile a lost send acknowledgement without issuing another send; confirm a test cannot bypass live permissions.

ED-AUTO-006 — Desktop and mobile Automation controls expose their actual platform/device capabilities through the same definition and run model. A mobile sensor, launcher action or background trigger is not interchangeable with a desktop window, process or device action. The selected executor, OS background restrictions and permission state determine availability and scheduling guarantees. Editing the graph on either platform preserves unsupported nodes for repair or execution on a compatible target; it cannot silently drop them. Switching hosted, standalone or hybrid installation neither duplicates schedules nor creates a private Automation store.

Reference detail — Atlas Planner/Automations screens; [planner.complete.md](https://github.com/CroakyJake12/9to1/blob/1f92cd888f59025cc684f0720163efdbc580f8e3/docs/specification/owner-references/2026-11-18-interface-refactor/baseline/retained-pack/modules/planner.complete.md)’s temporal, module and provider contracts; [automations.complete.md](https://github.com/CroakyJake12/9to1/blob/1f92cd888f59025cc684f0720163efdbc580f8e3/docs/specification/owner-references/2026-11-18-interface-refactor/baseline/retained-pack/modules/automations.complete.md)’s typed graph and durable execution contracts. References to historical Spaces Tasks are updated to the owner’s Actions Space taxonomy.

## 7.3 Frame, Wave, Motion and Sculpt

APP-MEDIA-001 — Each media project preserves original sources, stable editable objects, revision and nondestructive history. Save project and render/export are separate. Missing media/fonts, unavailable decoders/processors and interrupted jobs preserve the project with relink/retry/cancel. Fixture frames and waveforms are not real playback, source files or successful output evidence.

APP-PICTURE-001 — Composition and manual layers share one editable model with selections, layers, masks, text, crop/resize, transforms, adjustments, grouping/order, visibility and opacity. Layer and mask are separately selected targets. Painting a mask preserves original pixels; size, softness, opacity, visibility and inversion apply to that mask. Pointer hit testing and image rendering use the same transform. Export renders actual composition with declared format, dimensions, profile, alpha and destination; failed dependencies cannot produce false success or flatten the native project.

APP-WAVE-001 — Wave supports the multitrack timeline/mixer, import/record, trims/splits/moves, fades, gain, automation, effects/routing and supported waveform/spectral repair. Enhance Audio, Denoise and Split Stems are explicit tools with actual backend/resource capabilities. Transport, waveform, levels and output use one real timebase. Recording requires the selected device and armed track. Source offset, timeline start, duration and gain are distinct; numeric fades and handles edit the same envelope.

APP-WAVE-002 — Split Stems declares source, backend and output tracks; original media remains and generated clips carry provenance/alignment. Pending, Running, Failed and Complete reflect the real job. No output clips appear before success. Export uses the selected actual range/revision and audio settings. Missing media supports relink; cancellation preserves prior sources and completed work.

APP-MOTION-001 — Media bin, viewer, contextual inspector and multitrack timeline share clip/source identities and a single frame/timebase. Preserve editable titles, compositing, effects, keyframes, animation, audio alignment and registered advanced graph operations. A transition targets a particular cut with effect, duration, alignment and available source handles. Insufficient handles warn before application; edits remain undoable and original clips unchanged.

APP-MOTION-002 — Preview/proxy quality is distinct from final render. Render review shows source revision, sequence range, format, resolution, frame rate, audio and destination and validates dependencies before queueing. Project save, queued render and completed output are distinct states. Completion reports real output bytes/path rather than the existence of a queue entry.

Acceptance — Edit/undo an image mask and export alpha; trim an audio clip and edit fades; cancel/retry stem separation and compare alignment; reject a transition lacking handles; render a chosen sequence range and verify duration/audio. Reopen native projects after a failed export without losing editable sources.

Atlas anchors: picture, picture-mask, picture-export, wave, wave-clip, wave-stems, motion, motion-transition, motion-export. Frame is the current app display name; preserve compatible picture screen IDs and legacy aliases in Atlas v4.

### 7.3.1 Frame composition and object editing

ED-PICTURE-001 — PictureDocument owns artboard/canvas geometry, colour profile, background, editable element/layer graph, assets and revision. Raster, Vector and Hybrid describe content capability rather than separate incompatible applications. Each element stores type, parent/group, transform, visibility/lock, compositing properties and mask/effect references. Automatic object composition and Manual Layers are projections of this graph. Switching between them cannot flatten content. A semantic Subject/Background grouping may simplify presentation but remains inspectable as its actual elements and masks.

ED-PICTURE-002 — Selections include rectangle/ellipse, lasso, brush/refine, colour range and capability-backed semantic selection, with add/subtract/intersect/invert operations. Temporary selection differs from a saved mask/object. Convert selection to object creates a declared editable element and preserves source provenance. Move/resize/erase of an extracted subject can request background repair, but that repair is a separate generated element or revision with its own pending/failed/completed state. Failed repair must not silently bake an incomplete scene or erase the original subject.

ED-PICTURE-003 — Masks, clipping, opacity, blend order and adjustment scope are explicit. Crop changes the document/output boundary; trim-to-content, resize pixels and resize canvas are different commands. Raster effects such as levels/curves, exposure/colour, sharpening, blur, denoise and clone/heal are editable adjustments where supported; any baked operation creates a recoverable source revision. Vector paths reuse shared point/Boolean semantics. Text keeps characters, fonts, layout and glyph fallback information rather than becoming pixels on insertion. Ink reuses the shared drawing model and per-stroke resolved properties.

ED-PICTURE-004 — Generate, sketch-to-image, inpaint/outpaint and object replacement declare the input revision, mask/region, route/model, requested output and provenance. Preview outputs do not replace the native document until accepted. Retrying a generation preserves its prior result and selected source inputs. Imported PSD/SVG or other supported layered/vector formats retain representable structure and report unsupported effects; raster export declares dimensions, resampling, profile, alpha and metadata. A visual blur is not a secure-redaction promise; any redaction feature must describe its actual output behaviour.

ED-PICTURE-005 — Workflow A: import a layered composition, alternate Automatic and Manual views, extract/move a subject, cancel background repair and verify the original remains recoverable. Edit a mask, add vector text and change app theme; artwork/profile values remain unchanged. Workflow B: accept a generated replacement into a named element, undo it, relink a missing asset and export transparent output at a chosen size/profile. Reopen native data and verify layers, masks, text and generation provenance remain editable and distinct from exported pixels.

### 7.3.2 Wave audio, sequencing and generated components

ED-WAVE-001 — WaveProject owns sample rate/channel configuration, timebase, tempo map where used, tracks, markers/regions and native generated components. Tracks contain clips, gain/pan/mute/solo, record-arm, effects, automation and routing. Clips distinguish source range, timeline start, duration, gain, fades and stretch/pitch. Audio frames, musical bars/beats and display timecode are explicitly converted; rounding at view boundaries must not drift long arrangements. Wave and Motion share compatible audio primitives without requiring another app UI process to be open.

ED-WAVE-002 — Recording resolves a selected input, channel map, device grant and armed tracks. Monitoring and actual recording are separate. Support declared pre/post-roll, count-in, punch, overdub and loop/take policies. Write recoverable chunks incrementally; device loss stops or reconfigures only through the chosen policy and retains the partial take with truthful finalisation state. Clipping/meters reflect actual signal. A transport stop finalises the owned recording boundary and does not erase prior takes. Choosing a different input while armed makes its effect explicit before the next take.

ED-WAVE-003 — Clip operations distinguish trim, slip, split, ripple delete/move, ordinary delete, stretch and source-destructive edit. A ripple specifies affected tracks/range and respects locked tracks; it cannot silently desynchronise grouped material. Split creates timeline segments referencing the same source. Fades/crossfades use the same envelope in handles, numeric inspector and render. Snap declares grid/marker/transient/clip/musical targets. Undo restores the full affected arrangement, including moved neighbours, rather than only the selected clip.

ED-WAVE-004 — Mixer routing is a validated signal graph with explicit track/master gain, pan, inserts, sends/buses and automation. Prevent unsupported feedback cycles or require the engine’s deliberate feedback contract. Bypass differs from deletion. Parameter automation stores points/curves over the relevant timebase and retains units/ranges. Waveform and spectrogram are analysis projections with time/frequency selections; repair, Enhance Audio and Denoise name the target/range, configured steps and preview/bypass. Source media stays intact; cache absence recomputes analysis rather than losing edits.

ED-WAVE-005 — Generated music, sound effects and narration use editable native components whenever represented by Wave’s sequencer, instruments, patterns, synthesis/effect patch or TTS object. A narration object retains text, voice and prosody; a sound effect retains its patch. Rendered audio is a derived cache/output, not a replacement for structured source. Where a model supplies inherently opaque audio, identify that fact and preserve provenance instead of pretending editable notes exist. Split Stems records backend, resource requirements and alignment; separated clips share source timing and appear only after confirmed output.

ED-WAVE-006 — Export names sequence/range, routing, sample rate, channel layout, format/codec, loudness policy and destination. Warn on unsupported format/channel combinations and clipping according to the selected render policy. Real-time and offline render paths must apply equivalent declared effects; a missing plugin cannot silently become a successful dry mix. Workflow A: record an overdub, lose the input, recover a partial take, trim/split/ripple a grouped selection and undo. Workflow B: generate editable narration/SFX, automate one parameter, preview denoise, cancel/retry stems and export a known range. Verify alignment, output duration, original-source preservation and native component editability.

### 7.3.3 Motion video, compositing and animation

ED-MOTION-001 — MotionProject owns sequences, source assets, generated components and colour/cache settings. Each Sequence declares dimensions, pixel aspect, rational frame rate/timebase, tracks, markers, audio configuration and revision. Elements retain source range, timeline range, transform, effect/mask and animation references. Insert, overwrite, append, trim, roll, ripple, slip, slide, lift/extract and linked audio/video edits have distinct deterministic effects. A frame boundary derives from the sequence timebase, not a timeline pixel. Locked tracks and linked groups constrain multi-track operations with visible impact before commit.

ED-MOTION-002 — Source, proxy, decode cache, preview render and final output are separate. Proxy generation binds the same asset/time range and cannot change canonical clip timing. Missing/stale proxy is a repairable derived-state problem. Final export uses canonical sources at declared quality unless proxy-derived output is deliberately selected. Viewer frame and audio follow the same playhead; frame stepping and scrubbing identify when a preview is delayed or approximate. Replacing media checks duration/timebase/channel differences and preserves references through a reviewed relink mapping.

ED-MOTION-003 — Compositing uses explicit layer order, alpha/blend, masks/mattes, nesting, keying and adjustment scope. Property animation shares stable keyframe identity, value, time and interpolation; hold, linear and eased/Bezier curves have declared units and constraints. Moving a keyframe can snap in time without changing its value. Precomposition/nested sequences retain independent identity and cannot recurse infinitely. Transition at a cut names handles on both sources and the alignment; missing handles produce a scoped failure or explicitly chosen adjustment rather than stretching arbitrary frames silently.

ED-MOTION-004 — Advanced graphs use shared authoring infrastructure with Motion-specific node types, compiler/evaluator and ports; they do not run as Automations merely because the graph UI is shared. Titles remain editable text; generated clips, captions, tracking and rotoscope results retain source/revision/provenance and uncertainty where applicable. Applying AI analysis or a generated sequence edits the canonical project with inspectable objects, markers and effects whenever possible. It does not substitute a flattened preview movie for an editable timeline.

ED-MOTION-005 — Render jobs pin revision, in/out range, dimensions, rate, codec/container, colour/audio settings and asset dependencies. Validation distinguishes missing media/font, incompatible settings, unavailable encoder and insufficient destination space. Queue, render, finalise and verified output are separate. Cancel cleans only job-owned partial output and keeps the project. Workflow A: insert linked audio/video, ripple/roll a cut, add a valid transition and reject one lacking handles; keyframe a mask and undo a group edit. A VM-backed Windows application is not reported as native execution. Android apps participate through the same installed-app registry, Go, Files, taskbar and notifications where their host bridge works.

ED-OS-006 — Environment suspend/resume, updates, diagnostics and repair retain unsaved app state and distinguish guest/runtime updates from host updates. Unavailable acceleration, incompatible ABI, missing dependency, crashed app, remote-window loss and failed installation are actionable separate outcomes. Managed policy applies beneath Launcher/Go/Collection/Terminal invocation paths. Dangerous recognised OS commands preserve the source-defined warning, trusted authentication and final consequence confirmation through the system broker; authentication alone is not consent and an AI cannot approve its own operation. This protection does not pretend to prove arbitrary executable behavior safe.

ED-OS-007 — Workflow A: create taskbar layers, a Desktop Space, two Virtual Desktops and Desktop Pages; move windows, switch each concept independently and disconnect a monitor. Revert a bad layout, test keyboard recovery and inspect actual Quick Settings state. Workflow B: install a supported compatibility app, choose its backend, revoke a shared folder and suspend/resume without losing state. Exercise a package failure, inspect logs, roll back a failed update and confirm ordinary recovery left firmware/bootloader untouched. Validate the required UI and real backend separately.

Placements reference canonical app/activity and profile identity, so updates preserve placement and work-profile apps cannot silently launch as personal apps. ED-LAUNCHER-002 — Layout stores page/grid geometry, occupied cells, widget spans, folder membership and explicit ordering. Icon packs/overrides, labels, margins, dock/drawer/folder geometry, gestures, wallpaper/material and animations are configurable through versioned schemas. Gesture conflicts are detected; critical navigation remains reachable. ED-LAUNCHER-003 — Backup/import preserves semantic placements/settings and supported widget configuration without exporting credentials. Normal phone use remains available while Projector uses another display. ## 7.8 Projector

<a id="h.k6etzy5rdjth"></a>

### 7.8.1 Product boundary and experience gallery

ED-PROJECTOR-001 — Projector is the mobile display/activity platform and Samsung DeX alternative; Desktop is one experience within it. Its top-level Gallery answers what the connected screen should become. The intended first-party catalogue contains Videos, Games, Desktop, Music, TV, Haven, Presentation, Browser, Photos, Workspaces and Generated Experiences. These names identify product scope, not a claim that every experience has a working backend today. Each experience is delivered through an actual registered host, app, content route, workspace, generated interface or authorised remote device. Projector does not become a second package manager, file store or app registry.

ED-PROJECTOR-002 — A catalogue entry has stable ExperienceID, source/provider, name/artwork, launch strategy, interaction profile, persistence policy, required capabilities and content sensitivity. Duplicate identity from providers is resolved deterministically rather than producing duplicate tiles. Desktop, lean-back media, presentation, touch, controller and mixed-input profiles adapt layout/navigation to the activity. Gallery supports an appropriate large-screen tile layout and compact layout, keyboard/controller/touch navigation, current target identity and useful empty/unavailable states. Unavailable entries may explain requirements, but cannot present an active Open action when no executor exists.

ED-PROJECTOR-003 — Videos/Music/TV/Photos route selected permitted media or provider content to its genuine player; a catalogue category does not grant a subscription, codec, library or broadcast source. Games routes supported installed games, game projects or Play matches through their owning runtime and input capabilities. Browser and Haven open their actual surfaces; Presentation uses the canonical Present deck/session and separates audience output from private notes. Workspaces reference real layouts, apps and artifacts. Generated Experiences use canonical GenUI definitions/instances. Returning to Gallery preserves each owning app's declared state rather than copying its content into Projector.

### 7.8.2 Displays, sessions and capability negotiation

ED-PROJECTOR-004 — Display records distinguish ephemeral RuntimeID from optional proven StableIdentity, name, dimensions/density/refresh/rotation when known, transport, connection kind, trust and observation time. Native display and receiver transports share the contract without pretending to share capabilities. Wired, native wireless, virtual and receiver connections are reported only when known. Required capability states are Available, Unavailable and Unknown; Unknown cannot authorise launch, input, clipboard or media transfer. Relevant capabilities include Haven rendering, application launch/bounds, pointer/keyboard/touch/controller, audio/video transfer, clipboard, reconnect and presentation display support.

ED-PROJECTOR-005 — A session identifies target display, current/previous experience, controller, workspace reference, input devices, timestamps and real connection/activity state. Connecting, Gallery, Launching, Active, Suspended, Disconnected, Restoring, Stopping and Failed have distinct meanings. A selected tile becomes Active only after its actual host acknowledges the supported operation; a pending Android launch or remote request cannot imply rendered content. Source/target display loss, rejected launch and failed state update are separate outcomes. Switching experiences preserves or closes prior owned runtime resources deliberately, with failed transitions leaving an available Gallery/recovery path.

ED-PROJECTOR-006 — Trust is assigned to a specific display, independently of its friendly name. Private/Trusted displays may show permitted private content; Shared displays accept only shared-safe/public content; Public displays accept public content. User-visible trust changes and target selection occur on a trusted controlling surface. Private conversation, contact, notifications, presenter notes and file previews cannot leak merely because the phone connects to a screen. Re-evaluate trust, permissions and capabilities at execution and restoration, not only when the tile was listed. Revocation stops further restricted rendering/input and returns to an appropriate safe state.

ED-PROJECTOR-007 — Android application routes resolve canonical installed package/activity and user/profile identity and revalidate that the activity is permitted on the selected secondary display. They do not infer secondary-display support from installation alone. Launch uses the platform's explicit target-display mechanism and reports rejection, removed app or missing display distinctly. A failed external launch cannot be repaired by silently opening it on the private phone instead. Other platforms/runtimes require an actual declared provider; showing a Windows/Linux app name in Gallery is not evidence that the phone can execute it.

### 7.8.3 Phone control, routing and generated experiences

ED-PROJECTOR-008 — The phone remains usable while an external experience runs. A session controller can expose supported touchpad/pointer, keyboard, media, presentation or game actions without treating all experiences as desktop mouse targets. Input identifies the active SessionID, target and control owner; switching the phone to another app does not silently redirect queued Projector input. Pointer capture/release, keyboard focus and End/return controls remain reachable. Clipboard, audio route and notification disclosure are separately controlled. Disconnected input is rejected or explicitly buffered only where the target's contract permits it, never replayed unexpectedly into a later unrelated app.

ED-PROJECTOR-009 — The persistent bottom chatbox accepts requests to route the screen to an existing experience or create an appropriate generated interface. Resolve a request into a typed plan naming target display/session, actual experience/action, dependencies and relevant effects. Empty, Unsupported, Ambiguous, Blocked by capability and Blocked by trust are meaningful results. Ambiguous matching presents real candidates; a suggested fallback is not executed without the user's applicable intent. Newer requests cancel superseded planning, and an old async result cannot launch into a replaced session. Model interpretation does not confer app, content or device permission.

ED-PROJECTOR-010 — Requesting a generated experience invokes the shared Dulche/GenUI authoring contract rather than making the routing planner invent an executable tile. Validate the resulting typed definition, dependencies, actions and allowed runtime before mounting it. Saved/pinned/recent generated experiences retain canonical instance identity, state and revision. A stale or malformed definition remains inspectable/repairable; arbitrary executable payloads are not accepted as declarative UI. Opening, switching away, disconnecting and closing flush supported durable state and release the old surface. Generation failure preserves the previous usable experience and request context.

ED-PROJECTOR-011 — Remote experiences resolve trusted Mesh device identity and a currently reachable target, with the required device-action capability and source/destination policy. Discovery data may be cached for display, but launch rechecks reachability, target existence and allowed actions. The remote host returns an acknowledged outcome correlated to the request. Timeout or connection loss remains uncertain until reconciled; retry cannot silently duplicate an external app action. A remote Desktop route is distinct from streaming arbitrary content or transferring control. Each must have its own implemented capability and endpoint rather than being inferred from a successful device connection.

### 7.8.4 Persistence, recovery and resource policy

ED-PROJECTOR-012 — Recovery checkpoints retain the proven display identity, persistent experience/workspace references, relevant revision and updated time through a versioned settings/session store. Runtime display numbers are not durable identity. A returning display first resolves against the current registry; only eligible persistent experiences may resume after fresh trust/capability/permission checks. Session-only app launches require their own supported restoration semantics. When identity is unknown, reconnect is a new explicit target selection rather than a claimed automatic restore. A user Stop clears active restoration intent; unplugging may retain a recoverable checkpoint under the selected session policy.

ED-PROJECTOR-013 — Workspace recovery restores references and supported layout/state, with missing apps, denied artifacts and unavailable controllers shown individually. It cannot restore credentials, broaden grants or reopen private content on an untrusted screen. Persistence failure is visible and cannot be reported as Saved. External-display resize/rotation and phone posture changes reflow the same session without losing drafts. Low-power/low-memory operation bounds caches, adapts render work/refresh where supported and stops idle resources while preserving the owning apps' unsaved state. External display capability never becomes a prerequisite for ordinary mobile Code, Sites, Stacks, Games or Virtual Device use.

ED-PROJECTOR-014 — Workflow A: connect a new public display, inspect target/capability state and attempt a private experience. Set an appropriate trust policy on the phone, open the actual Desktop host, launch an eligible installed app, reject an ineligible activity and return to Gallery. Use supported phone input while a different phone app remains usable; switch the target and verify old input/request results cannot reach it. Test a real launch failure and distinguish request acceptance from actual activation.

ED-PROJECTOR-015 — Workflow B: route a Present deck to audience output while notes stay private; use the bottom chatbox to select a registered experience, inspect an ambiguous result and then generate/save a validated interface. Disconnect during loading, reconnect with and without proven stable identity, revoke a dependency and recover without an invented successful mount. Workflow C: restore a workspace containing an unavailable app, route Desktop to a trusted remote target, lose the acknowledgement and reconcile it before retry. Verify durable state, privacy exclusions, bounded resources and actual provider outcomes.
