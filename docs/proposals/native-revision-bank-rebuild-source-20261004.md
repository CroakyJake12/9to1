# Native Revision Bank source proposal

This proposal exposes canonical Space Revision Bank metadata through a native Haven scene. It stores membership and category changes through the existing guarded SpaceRegistry settings owner, without copying artifact payloads or creating a second bank store.

The native route requires an explicitly supplied OwnedSpacesSession. That session checks the original provider, settings instance, identity source, actor source, ownership receipt authority and SpaceLocalStoreAuthority. It does not create an actor or ownership receipt, supply a host write decision, or convert Home compatibility or Core read access into Spaces write authority. An installed application still needs a genuine configured Spaces action and ownership port; unavailable composition refuses activation.

The page retains its admitted operation tasks before callbacks, keeps the exact acknowledged canonical mutation result independently of later presentation, bounds pending and failed tasks, and exposes a coalesced CloseAndDrainAsync. Rendering checks the captured original owner before and after each native notification boundary. Retirement withdraws publication, and external close joins the actual tasks before control cleanup. Synchronous Dispose requests retirement and does not prove a drain.

The Spaces route adds a Revision Bank action and fixes the selected Space deletion callback to invoke its owner once. Its new selected action drain covers Bank opening and deletion only. The predecessor's other asynchronous handlers and the shell's synchronous tab/history disposal still require their own lifetime integration; no complete shell or provider drain is asserted.

Four composition Facts and six native AvaloniaFacts are authored, UNCOMPILED and UNRUN. They use real temporary guarded settings owners for original-provider pairing, denied admission, physical commit with delayed acknowledgement, stale revision refusal, bounded failed task retention, deletion once, and synchronous native retirement or owner replacement. Controlled fixture actors and receipts are test inputs, not installed Home authority. Native control invocation is headless and does not demonstrate Windows installation or pointer delivery.

The source basis is isolated commit 515e5fb5596f47332d24892afa67155ef7a192b3, which contains the six reviewed Study owner prerequisites over its Foundation parent. This is a fresh source proposal. Earlier unavailable drafts and their review status do not certify these bodies. Fresh whole-source review and actual affected compilation and owning checks are required before adoption.

Source Open/Create authorization, registered artifact embeddings, cross-process Spaces manual write decisions, full legacy handler retirement, acquired-page shell close integration, and installed Windows acceptance remain incomplete. The standalone Cards application is a separate delivery requirement.
