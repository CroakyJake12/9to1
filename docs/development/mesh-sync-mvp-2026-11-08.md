## 1. Required MVP user flow, pinned before any code (owner-approved payload: the Boards document)

> One private LAN, two devices **A** and **B**, both running the same 9to1 desktop build from this checkout. A pairs with B by one-time fingerprint-bound pairing. The user explicitly enables a `mesh.sync` grant for the peer (default OFF). The user edits one **Boards** document on A and saves through the normal save/close lifecycle. Within one round trip B shows the converged board with the revision number, origin device and timestamp recorded in the Mesh view. B restarts the app and the content is still there. A concurrent edit on both ends produces a **visible conflict record with both divergent revisions preserved** — never a silent overwrite, never a wall-clock winner. On A, **Revoke** stops any further mutation reaching B.

Out of scope for this MVP, deliberately: Spaces `Local / Mesh / Cloud` conversation placement, Automations device-level action catalogue, Admin cross-account Business Mesh, shared compute pools, cloud relay, and any non-LAN transport. Those remain mandatory specification work, unchanged by this document.

## 11. U5 design fixed before coding (so the handoff does not have to re-derive it)

Durable queue and restart replay will **not** store board payloads in Mesh state. Storing a copy of user content inside `mesh/state.json` would duplicate canonical data in a place the Boards owner does not validate, and it would go stale the moment the local board is edited again. Instead:

- `MeshSyncIntent` (persisted in `MeshPersistentState` version 3, capped like the task list): `ResourceId`, `ResourceType`, `PeerDeviceId`, `State` (`QueuedOffline` / `Unconfirmed` / `Acknowledged` / `Rejected` / `ConflictReported`), `RequestedAt`. No payload, no content hash.
- On `ConnectionChanged → Connected` for a peer, the coordinator re-captures the **current** complete state from that resource's owner and offers it again with a fresh operation id. Dedupe therefore relies on the content-hash rule rather than the operation-id window, and a board that was edited while offline syncs its newest state rather than an old snapshot.
- Restart replay is then just this: load state v3, see un-acknowledged intents, and replay them when the peer is present. The migration follows the existing version-bump pattern in `InitialiseAsync` (`WorkMembers`/`WorkMessages`/`WorkItems` already do exactly this).
- Required checks: an offline peer leaves a persisted intent that survives constructing a new coordinator over the same state store and is delivered when the peer next appears; a re-captured newer state replaces what would have been sent; an acknowledged intent is not replayed; state v2 loads and migrates without losing peers, tasks, conflicts or the applied-operation window.

## 17. U5 landed: durability without duplicating content (suite now 73/73)

`MeshPersistentState` is at **version 3** with `SyncIntents`. An intent is `(ResourceId, ResourceType, PeerDeviceId, State, Detail, RequestedAt)` and deliberately carries **no payload and no content hash**, so Mesh state never holds a second copy of somebody's board. `RecordDeliveryAsync` persists an intent when a change did not land (`QueuedOffline`, `Unconfirmed`) and clears it when the peer answers, refuses or conflicts. `ConnectionChanged → Connected` triggers one replay pass per peer, which **re-captures from the owning feature** — so a board edited while the peer was away replays as the new content rather than a stale snapshot. A version-2 state, which genuinely has no `SyncIntents` field, is read through a null-safe accessor rather than force-unwrapped, and migrates by the same pattern the existing work-mode fields already use.

## 19. Reading the Boards host caught two defects in code I had written only minutes earlier

`BoardsLocalDocuments` fixes the real layout: line 103 puts boards at `<DataDirectory>/Boards/profiles/<sha256(profileId)>/drafts`; line 107 constructs a **fresh** `JsonFileHavenBoardStore` on every construction (the desktop host does this per operation at `App.UnifiedWorkspaceHost.cs:741` and `:785`); line 116 re-records every `*.9to1board` in that one directory into `recent.json` when the scope opens; line 120 names a board `id.ToString("D") + ".9to1board"` — the **dashed** Guid form.
