Use the main intake/common gates before executing any family: exact Smoke Tester artifact/deployment identity, source/build binding, genuine authenticated app sessions, isolated accounts/data and required shared-runtime/provenance evidence. Admit Windows and applicable gated web independently and keep their results separate. Repository code presence and unit-test success cannot substitute for the packaged workflow.

The product journey uses the actual canonical 9to1 project and an approved bounded change, with unrelated user changes recorded before starting. No sample repository, disconnected project copy, simulated tool response or generic Saved-Agent test is an acceptance substitute.

1. Launch the admitted standalone Assistants product. Select or create a configured development Assistant and record AssistantID, conversationID, canonical Files/Spaces/Dev ProjectID, source baseline, TaskID and RunID.
2. Open Dev directly from the Assistant conversation. Inspect source and perform the bounded authorised typed edit; inspect real source and AI-pass diffs with explicit baselines.
3. Run actual build and meaningful tests in the selected environment, inspect semantic diagnostics, and demonstrate a supported real debugger breakpoint, step and variable inspection.
4. Inspect recorded AIChangeSet, contributor attribution and actual build/test/debug results; create a checkpoint containing genuine outputs and evidence.
5. Apply live steering and pause/resume at a safe boundary. Inspect worker instruction propagation and preserve valid work.
6. Close the conversation and app surfaces, reopen the same Assistant/Task and resume remaining approved work. Compare canonical identities, configuration, project references, accepted checkpoints and effects.
7. Separately deny initial access and revoke an existing grant before a subsequent read/mutation/process/VM action. Prove no effects outside the grant and no queued stale-authority execution.
8. Reconcile current accepted source/output revision, explicit Task/Run attempt relationships and every default/user-added test before any final verdict. An unexecuted, stale, blocked or missing result stays unsatisfied.

Assistant identity is distinct from conversation, Task and delegated worker identity. Documented Run attempts may vary during recovery while the canonical Task and Run relationships remain preserved. Native Home/shared-services dependencies and applicable Spaces-runtime dependencies must be satisfied through product contracts. Web uses corresponding authenticated shared services.
