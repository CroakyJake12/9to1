## Release-isolation correction

The known restaurant conversation, sample recent titles, composer prompt, Qwen3.6 visual selection and illustrative work cards originate in the isolated `apps/Web/Spaces/Tests/Visual` executable and JSON input. The release guard protects that separation rather than deleting genuine user content.

Owned repository files:

- `apps/Web/Tests/verify-production-isolation.cjs`: scans explicit public artifact bytes, raw and decompressed gzip/Brotli, for known fixture ownership and a combination of reference data signatures in UTF-8/UTF-16LE/UTF-16BE. It deliberately does not prohibit model names. It checks the real restored project closure and, when supplied, actual SDK root Compile/ProjectReference/ReferencePath items. A legitimate CUI `Visual` directory/assembly is allowed; exact fixture identity remains forbidden.
- `apps/Web/Tests/production-isolation.test.cjs`: reusable negative controls with explicit actual bundle/assets/project arguments and temporary controlled leaks. It never accesses account/profile data, launches a browser/provider, or modifies the sealed bundle.
- `apps/Web/Tests/verify-publish-receipt.cjs`: the existing receipt validator now rejects leaked fixture assets even if their file hashes match an otherwise self-consistent receipt.
- `apps/Web/Tests/ci/run-ordinary-web-publish.py`: requests actual evaluated compile/reference items from its ordinary Build, checks isolation before sealing, and records the result. CJS validation sources are included in its source custody snapshot.

The current actual immutable0e24 bundle contains346 files including230 compressed variants and zero known fixture signatures. The current real restored production graph has47 project references and no visual/test project. These are separate evidence scopes: historical published artifact bytes versus the current restored graph.
