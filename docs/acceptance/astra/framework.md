## Execution protocol for the eventual candidate

Run each family against its exact Smoke Tester-qualified candidate, source head and package/deployment identity. Keep Windows and web results separate and record every advertised architecture/browser/backend/hardware/capability combination. Browser clients use authenticated shared web services; native clients negotiate compatible Home and mandatory core. Include 9to1-OS and any other declared supported platform obligations rather than assuming platform parity from one run. Record unavailable capabilities as explicit platform differences with canonical authorization; an absent capability is not automatic exemption.

For native interface families, use the actual installed Windows surface: screenshots and genuine keyboard/pointer/touch where supported, OS accessibility/screen-reader observations, focus/shortcut behavior, populated and empty/loading/error/overflow states, 200% scaling, contrast/themes/reduced motion and narrow/touch layouts. A semantic tree, a browser wrapper, an API success or a static screenshot alone does not prove native rendered accessibility/input or a functioning native artifact. Shared services with no required visible surface use direct API/state checks and retain the reason interface evidence is inapplicable.

Use production permission/identity/target/runtime paths with isolated permitted fixtures. Establish actual effects and save/close/reopen persistence. Induce interruption, changed grants, partial failure and concurrency safely; reconcile completed/uncertain effects before replay. For model interruption, show actual execution on another eligible authorized route, including configured capable local inference, while the same canonical TaskID/RunID/root and accepted checkpoints continue. A mocked fallback or replacement task does not satisfy continuity.

Keep exact command/API transcripts, environment/capability profiles, rendered evidence, durable identifiers/revisions, failure/recovery records and test result revisions. Invalidate affected evidence after changes. Successful builds/source presence are supporting artifacts only. All product statuses remain NOT EXECUTED until the candidate gate permits genuine tests; missing/stale/blocked/not-run evidence remains visible.
