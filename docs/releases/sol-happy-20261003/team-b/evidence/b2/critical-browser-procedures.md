# Concrete blocked browser procedures

All procedures below are **NOT_RUN**. They require a real registered owning editor, authenticated authorised staging services, declared browser versions and exact frontend/backend deployment identities. Use isolated test accounts/data. Domain-probe PASS does not satisfy these procedures.

## B2-WRITE-BROWSER-SEMANTIC-ROUNDTRIP

Source basis: Write structured document engine, donor parity, native/foreign formats, collaboration and acceptance sections. Existing supporting source tests: `WriteSelectionFormattingTests.Selection_formatting_only_changes_highlighted_text`, `Selection_formatting_spans_existing_runs_without_touching_outer_text`, `Comment_targets_selected_text_range`; `WriteDocxFidelityTests.Rich_docx_export_emits_word_formatting_and_round_trips_supported_features` and `Docx_import_reads_independent_wordprocessingml_formatting_and_external_link_metadata`. These unit/domain tests remain supporting evidence, not hosted/browser acceptance.

Fixture: create a native Write document with body `Alpha beta gamma`, another paragraph with existing italic/bold/underline runs, nested Sections and heading navigation, a reusable custom style, a 2×2 table with independent padding/borders, a real source image and reference. Set a genuine header/footer and page geometry. Record actual DocumentID, SectionIDs, ObjectIDs, StyleID, revision and owner/reader ACL. Keep foreign DOCX/ODT fixtures authored independently through the selected maintained Writer donor; do not use only files produced by the same exporter under test.

1. In the real structured editor, select offsets 6–10 in `Alpha beta gamma`, using ordinary caret/keyboard selection. Apply Bold through the applicable contextual toolbar, then through the same typed action on a reset fixture. Assert exact runs `Alpha ` unbold, `beta` bold, ` gamma` unbold; concatenated text remains exact. Assert selection targets the existing ObjectID and normal undo restores exact pre-edit text/style.
2. Select a range spanning existing runs, change font and add a comment. Assert outer fragments retain original font and selected fragments retain unrelated italic/bold/underline attributes. Assert comment ObjectID/range/content refer to the selected text rather than whole document or visible pixels. Verify expected change/revision and audit actor via the owning API.
3. Save, close the editor, clear the browser client state and reopen in a second authorised clean client. Read the canonical owning document via its typed API. Assert DocumentID/SectionIDs/ObjectIDs, exact run content/styles, table structure/formatting, image source reference, header/footer and comment range/content. Assert durable revision exists in history and saved UI never precedes authoritative content+metadata commit.
4. Move/rename through Files while open. Assert browser and second client resolve the same DocumentID, content/revision and links. Names/path change only; no unrelated import/copy appears.
5. Export DOCX and ODT through the declared donor path. Reopen in the selected actual donor application and independently inspect runs, page/header/footer, lists, tables, image/reference and review constructs within the declared mapping. Then import each as an explicitly **new** canonical document. Record the newly assigned ID, save/close/reopen it and assert that new identity is stable. Do not require an external interchange import to retain the source native DocumentID unless the declared format contract promises it. Native `.9to1w` round trips must preserve its full native IDs/model/unknown-compatible optional data.
6. For unsupported native semantics, assert CompatibilityIssue names the precise affected object/property and exact degraded/omitted/blocked behavior before destructive commitment. Do not count exporter→same importer self-consistency as donor fidelity; compare independent donor opening and semantic content.
7. Repeat under reader ACL, revoked sharing and AI Read-only. Assert no content/revision mutation and no private semantic context leakage. AI Write with Suggest must create a real suggestion; acceptance/rejection controls determine committed content. Prior trust never overrides object ACL.
8. Open two editing clients at base revision R. Apply edits to independent objects; verify both persist. Apply incompatible edits to the same range/style from R; assert revision conflict/defined resolution and preserved recoverable alternatives. Never assert only that a toast appears: read final text/style/history and check no edit silently vanished.
9. Interrupt an isolated save; previous durable revision remains readable and unsaved draft remains visibly recoverable. Resume/retry and assert one logical operation, no duplicate revision/objects and correct committed content. Capture backend/second-client before/after values and trace, not a success label.

## B2-DATA-BROWSER-CALC-GRID-RECALCULATION

Source basis: Data workbook/spreadsheet, Calc-compatible formula engine, keyboard/accessibility, protected mutation and acceptance sections. Existing donor-path corpus: `Data/Tests/test_calc_formula_corpus.py` and `Data/Tests/RuntimeProgram.cs`. At inspection, neither the primary Python nor `/usr/bin/python3` could import `uno` or `duckdb`. Available `soffice --version` reported LibreOfficeDev 26.8.0.0.alpha0; compatibility with the selected accepted donor/runtime has not been validated. No donor-path test was run.

Fixture: genuine Calc-backed workbook with A1=2, A2=3, A3=4 and B1=`=A1+A2*A3`, B2=`=SUM(A1:A3)`, B3=`=$A$1+A2`, B4=`=A1^3`, B5=`=AVERAGE(A1:A3)`, B6=`=COUNT(A1:A3)`, B7=`=MIN(A1:A3)`, B8=`=MAX(A1:A3)`. Add unrelated sheet/cells to distinguish dependency updates from eager full-workbook computation. Record canonical ProjectID/WorkbookID/SheetID, formulas, typed values, base revision and owner/reader permissions.

1. Open through real browser grid and select A2 using keyboard. Inspect accessible coordinate, semantic value/type and formula-bar binding. Enter 5 via normal cell/formula editing; assert real canonical cell edit and dependent displayed values B1=22, B2=11, B3=7, B4=8, B6=3, B7=2, B8=5. B5 must reflect 11/3 using declared Calc numeric precision; do not compare locale-formatted text to an invented precision policy.
2. Read formulas and typed cell values through the actual owning Data API and independent client. Assert formulas remain formulas; no browser calculation/screenshot/success string stands in for donor recalculation. Collect dependency instrumentation showing which dependants recomputed; unchanged visible numbers alone do not prove efficient dependency calculation.
3. Save through canonical storage, close both clients and reopen cleanly. Assert stable workbook/sheet identities, typed values, formula text, exact revised content and durable revision/history. Rename/reorder Sheet and move/rename source through Files; assert stable references and recalculation still resolve.
4. Export supported ODS/XLSX and open through real selected Calc runtime; inspect cells/formulas and representative structural named-range/validation/sort/filter behavior. Import as a new canonical project when appropriate, then verify its own stable reopen identity. Do not infer full Calc parity from this eight-formula corpus.
5. Reader/protected-sheet edits must fail without mutation. AI-requested A2 edit must require explicit approval for **that action** even after AI Write/Always Trust; decline and assert unchanged revision/value. Approve once, verify exact mutation, then require fresh approval for another AI edit.
6. Concurrent independent edits retain both values; incompatible same-cell/formula edits yield owning revision/conflict behavior. Inserting/deleting rows must adjust references through Calc semantics while independently identified Data objects retain identity.
7. Execute read-only SQL against explicitly displayed local analytical target. Assert actual typed result and execution identity/target; failed next query preserves previous valid results. A browser SQL simulation or sending SQL text to AI is a failure.
8. For isolated live-database mutation only, assert target/classification/impact, required real checkpoint/transaction identity and explicit confirmation. When required protection cannot be established, assert no SQL mutation. Verify resulting rows/schema and distinguish attempted/successful rollback. Never fault-inject into production.
9. Interrupt isolated save/refresh; assert previous valid workbook/result survives, unsynced state remains visible, and retry does not duplicate cells/records or claim remote save. Capture exact semantic before/after values, browser trace, donor/runtime/deployment identity and resource measurements.
