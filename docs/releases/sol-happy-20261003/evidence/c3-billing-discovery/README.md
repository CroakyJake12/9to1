Exact missing production bridge: inbox schema stores event ID/type/created/hash, not raw provider bytes or current object identity. `OrganisationBillingService.ProcessProviderEventAsync` requires an authenticated canonical Guid and `ITrustedBusinessBillingVerifier.VerifyAsync`; its output must already establish merchant, existing subscription/account/org binding, actual effective dates and approved PolicyVersion. No maintained production verifier/binding registry is configured. `SubscriptionPurchaseService.ProcessProviderEventAsync` additionally requires `ITrustedBillingSettlementVerifier` and `IEntitlementMonthlyPricePolicy`, and an existing account-bound purchase and quote; the receipt adapter cannot derive those from the inbox. `OrganisationService.ApplyVerifiedBillingTransition` is internal to canonical C# state and not a hosted Worker effect transport. Canonical filesystem durable storage is not an approved multihost transactional bridge. Source pins are explicit in source-pins.json; proposed Accounts source is not assumed adopted.

A real consumer therefore still needs owning provider bindings, approved commercial model/lifecycle policy, actual current-object verification and a approved canonical transport/store. No balances, entitlement models, prices, guessed policy, Stripe request, remote resource or charge was added.
